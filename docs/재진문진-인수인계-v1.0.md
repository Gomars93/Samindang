# 재진용 경량 outcome 재입력 문진 — 인수인계 v1.0

- 작성일: 2026-08-10
- 배경: 삼인당 AI 경영실 action-register A-038. 갱년기 불면 Pilot(니치패널 §21 outcome 데이터 구조) 성과추적 전제조건.
- 관련 기존 문서: `삼인당_태블릿_상세문진_Master_Spec_v1.0.md` §4.4A(MENOPAUSE_SLEEP), §13.7(방문/환자 데이터 계층), `갱년기불면-수면위생교육-v1.0.md`(교육자료, A-036)

---

## 1. 이게 왜 필요한가

§13.7.2에 이미 "문진 없는 재진"(`judgment_ref: null`) 케이스가 정의돼 있지만, **그 경우 판단을 기록할 UI가 없다**고 명시돼 있다(§13.7.2, "의도적으로 남겨둔 다음 스프린트의 갭"). 이 문서가 그 갭 중 갱년기 불면 Pilot에 필요한 부분(outcome 재측정)만 채운다 — "문진 없는 재진" 전체 UI를 다 만드는 게 아니라, 최소 범위로 좁힌 스코프다.

목적: 초진 때 MENOPAUSE_SLEEP(MS_01~07)을 완료한 환자가 재진으로 왔을 때, 초진 문항 전체를 반복하지 않고 **outcome 재측정 + 실천여부 확인만** 짧게 받는다.

## 2. 진입 조건

- 원장이 기존 `patient_id`를 지정해 재진 `visit`을 생성한 경우(§13.7.1 원칙 그대로 — 이름/전화번호 자동매칭 절대 금지)
- 그 `patient_id`의 이전 submission에 `modules.sleep`(MS_01~07 포함, primary_concern === sleep)이 존재하는 경우에만 이 경량 문진 노출. 없으면(다른 주호소였던 재진 등) 이 흐름 자체를 스킵 — 강제로 안 묻는다.
- **미확정 — 개발 판단 필요**: 진입 조건 판정을 프론트에서 이전 submission 조회로 할지, 원장이 방문 활성화 시 수동으로 "재진 outcome 문진 보여주기" 토글을 켜는 방식으로 할지. 후자가 더 안전(문진 없는 재진 오분류 방지)하지만 원장 조작 단계가 늘어남 — 트레이드오프 판단은 개발 담당.

## 3. 화면 구성 (REV_ prefix, 신규)

**REV_01** `revisit_total_sleep_time` — single_choice — 필수
질문: "요즘 실제로 자는 시간은 하루에 대략 얼마나 되나요?"
options: 동일 (MS_04와 동일 옵션셋 재사용) `7h_plus/6_7h/5_6h/under_5h/unknown`

**REV_02** `revisit_awakenings` — single_choice — 필수
질문: "자는 동안 보통 몇 번 정도 깨시나요?"
options: 동일 (MS_06 재사용) `once/two_three/four_plus/varies/unknown`

**REV_03** `revisit_return_to_sleep` — single_choice — 필수
질문: "깬 뒤 다시 잠들기까지 보통 얼마나 걸리나요?"
options: 동일 (MS_07 재사용) `within_15m/15_30m/30_60m/over_60m/cannot_return/unknown`

**REV_04** `revisit_sleep_hygiene_adherence` — multi_choice — 필수 — exclusive: `[none]`
질문: "지난번 안내드린 것 중 해본 게 있으면 표시해주세요."
options: `fixed_wake_time`(기상시간 고정) / `stimulus_control`(졸릴 때만 눕기) / `less_nap`(낮잠 줄이기) / `less_caffeine_alcohol`(저녁 카페인·술 줄이기) / `less_screen`(자기전 화면 줄이기) / `daylight`(낮 햇빛) / `bed_for_sleep_only`(침대는 잠만) / `bedroom_environment`(침실 서늘·어둡·조용하게, 2026-08-10 8번째 팁 추가분) / `none`(해본 게 없음)

**주의(A-036 검수 결과 반영)**: 이 화면은 "몇 개 실천했는지" 점수화 표현을 쓰지 않는다 — 인쇄카드에서 이미 그 프레이밍이 "성취 점수판처럼 읽혀 실패 메시지와 충돌한다"는 이유로 삭제됐다(`갱년기불면-수면위생교육-v1.0.md` §2 참조). 이 화면은 임상 데이터 수집(outcome 추적)이 목적이지 동기부여 장치가 아니다 — UI 카피에서 "잘하셨어요/부족해요" 류 평가성 표현 넣지 않는다.

## 4. 데이터 저장

- `visit` 레코드(§13.7.2 데이터모델)에 이 4개 값 저장. 기존 `judgment_ref: null` 케이스에 새 필드 추가 필요 — 정확한 스키마(예: `revisit_outcome: {...}` 서브객체)는 개발 담당 판단.
- Doctor 화면에서 초진 MS_04/06/07 값과 이번 REV_01/02/03 값을 **나란히 비교 표시**할 수 있어야 함(전후비교, 니치패널 §21 baseline_outcome/followup_outcome 구조와 대응).
- 환자 식별정보 미포함, `patient_id`/`visit_id`로만 연결(기존 원칙 그대로).

## 5. 범위 밖 — 하지 않는 것

- "문진 없는 재진" 전체 UI(비수면 주호소 재진 등)는 이 스코프 아님. 다른 스프린트.
- 실천 자가체크(REV_04) 결과를 근거로 자동 처방·자동 코멘트 생성 안 함 — 원장이 화면 보고 직접 판단.
- 명리 관련 재계산 없음(출생정보 불변이라 재계산 자체가 불필요, 이미 저장된 값 조회만 — `동의화면-인수인계-v1.0.md` §4 참조).
