# EMR → 초진트래커(Google Sheets) 자동 연동 — 인수인계 v0.1

- 작성일: 2026-08-25
- 작성 세션: 클라우드 세션(`claude/sigma-chart-api-access-pn31wv`)
- 상태: **탐색 단계, 코드 미작성.** 이 문서는 클리닉 LAN 안에서 실행될 로컬
  세션(또는 담당 개발자)에게 지금까지 확인된 사실과 남은 작업을 넘기기 위한
  스냅샷이다.

## 1. 배경

삼인당 초진 유입 트래커(Google Sheets)를 지금까지 원장/직원이 매 건 수기로
입력해왔다. 최근 EMR 쪽에 외부 연동용 API가 생겨서, EMR이 이미 갖고 있는
값은 API로 자동 추출해 트래커에 채우고 사람이 판단해야 하는 값만 수작업으로
남기는 것이 목적이다. **전체 자동화가 아니라 부분 자동화**다 — EMR에 없는
값(유입경로, 제시치료, 전환유형 등 영업/상담 판단)은 앞으로도 계속 수작업으로
입력한다는 것을 요청자가 명시적으로 확인함.

## 2. 왜 로컬에서 해야 하는가 (중요)

EMR API 주소가 `https://192.168.0.22:57443/...`로, **사설 LAN 대역
(192.168.0.0/16) IP다.** 이 클라우드 세션에서 `WebFetch`로 직접 접속을
시도한 결과 `connect ECONNREFUSED 192.168.0.22:57443`로 확인됐다 — 즉
인터넷 경유로는 원천적으로 도달 불가능하다.

`docs/RUNBOOK_LOCAL_HANDOFF.md`가 이미 문서화한 "로컬 handoff 서버는 클리닉
LAN 전용, 인터넷 비노출 전제"와 동일한 제약이다. 따라서:

- **실제 API 연결 테스트, 개발, 실행은 반드시 클리닉 LAN 안의 머신**(예:
  기존 로컬 큐(`.claude/queue/`)가 도는 Windows PC, 또는 `server/` 로컬
  handoff 서버가 도는 원장 PC)에서 진행해야 한다.
- 이 클라우드 세션은 스펙 정리/코드 스캐폴딩까지만 도울 수 있고, 실제 호출
  검증은 못 한다.

## 3. 확인된 사실

### 3.1 EMR API
- Base: `https://192.168.0.22:57443`
- 가이드/문서 엔드포인트: `/external/v1/guide` (클리닉 LAN 안에서만 접근
  가능 — 로컬 세션에서 브라우저나 `curl -k`로 직접 열어서 엔드포인트
  목록/인증 방식을 확인해야 한다. 이 문서 작성 시점엔 내용을 아직 못 봄)
- 인증 토큰: 사용자가 두 차례 파일로 전달함 (`sigmachartapi.txt`). **최신
  것(두 번째 업로드)이 유효 토큰이고, 첫 번째 것은 폐기됨**을 사용자가
  확인함. **실제 토큰 값은 이 문서/커밋/로그 어디에도 기록하지 않는다**
  (`CLAUDE.md` 시크릿 규칙) — 로컬에서 `.env` 등 git-ignore된 위치에
  보관할 것.
- HTTPS인데 사설 IP + 비표준 포트(57443)라 self-signed 인증서일 가능성이
  높음 — 로컬에서 실제 호출 시 인증서 검증 방식 확인 필요.

### 3.4 자동/수동 컬럼 분류 (제안, 확정 아님)
| 컬럼 | EMR로 자동 채움 가능? | 비고 |
|---|---|---|
| 날짜 | 가능 | 방문일 |
| 환자명 | 가능 | |
| 원장 | 가능 | 담당의 |
| 차트번호 | 가능 | 기존에도 한약 리마인드 매칭용으로 수기 입력 중이던 필드 |
| 수납액 | 가능(추정) | EMR에 수납 데이터가 있다면 |
| 처방명 | 가능(추정) | 한약 처방 등 |
| 초진구분(신규/재초진) | 조건부 | EMR 방문 이력으로 유추 가능할 수 있음 — 로컬에서 API 응답 보고 판단 |
| 유입경로 / 세부 | **불가 — 수작업 유지** | 마케팅/상담 판단, EMR에 없음 |
| 제시치료 / 전환유형 | **불가 — 수작업 유지** | 상담 결과, EMR에 없음 |
| 주소증 | 조건부 | EMR 진단명/주호소 필드가 있다면 가능할 수도 |

이 표는 API 가이드 문서를 실제로 본 뒤 로컬 세션에서 검증/수정해야 한다.

## 4. 열려 있는 질문 (로컬 세션이 이어서 확인할 것)

1. `/external/v1/guide` 실제 내용 — 엔드포인트 목록, 인증 헤더 형식(예:
   `Authorization: Bearer <token>`인지), 환자/방문 단위 조회 API가 있는지,
   날짜 범위 쿼리가 되는지.
2. EMR 응답의 환자 식별자가 트래커의 "환자명"과 어떻게 매칭되는지 (동명이인
   처리 포함) — 기존 트래커는 이름 기반이라 위험 요소 있음. 차트번호를
   1차 키로 쓰는 게 안전할 가능성이 높음.
3. 자동 채움 방식: Google Sheets API로 직접 쓸지, Apps Script(시트에 내장,
   트리거 기반)로 EMR API를 호출하게 할지 — LAN 제약상 Apps Script는 Google
   서버에서 실행되므로 사설 IP(192.168.0.22)에 못 붙는다는 점 주의. 즉
   **로컬 머신 → EMR API 호출 → 로컬 머신 → Google Sheets API 쓰기** 형태가
   유력해 보임(Apps Script 단독으로는 불가).
4. 실행 주기/트리거: 매일 배치 vs 실시간 vs 수동 버튼.
5. 실패/중복 방지: 이미 트래커에 있는 행을 다시 채우지 않도록 하는 idempotency
   키(차트번호+날짜 등) 설계.

## 5. 범위 밖 — 하지 않는 것 (지금까지 확인된 것 기준)

- 유입경로/제시치료/전환유형 자동 판단·자동 입력 — 명시적으로 수작업 유지
  하기로 확인됨.
- Sigma(BI 차트) 쪽 연동은 이번 스코프에서 별도 확인 안 됨 — 처음 질문
  ("시그마 차트 api 접근 가능?")이 실제로는 이 EMR API를 가리키는 것으로
  보이나, Sigma Computing 같은 별도 BI 툴 연동을 의미했다면 이 문서 범위
  밖이니 확인 필요.
