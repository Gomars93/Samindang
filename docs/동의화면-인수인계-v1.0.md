## 1. BIR_00 — 출생시간 활용 동의 (신규, §22 BIRTH INFORMATION 최상단에 삽입)

기존 §22 화면 상단 설명("체질 분석에 참고하기 위해 출생정보를 확인합니다") 바로 아래, BIR_01(생년월일)보다 앞에 배치.

문구:

> 출생시간은 박경남 원장님의 명리학적 해석에 활용됩니다. 모르시면 생략하셔도 됩니다.

variable:
`birth_time_consent`

input:
button (2지선다)

options:

| label | value |
|---|---|
| 동의 | agree |
| 비동의 | disagree |

required:
Y

### 분기 규칙

```text
birth_time_consent = agree
  → BIR_02(양력/음력), BIR_03(출생시간 확실성), BIR_04(출생시간대) 그대로 진행

birth_time_consent = disagree
  → BIR_02~BIR_04 전체 skip
  → birth_time_certainty, birth_time_branch = null 처리 (unknown과 구분: "동의 거부"로 별도 로깅)
```

**미확인 — 확인 필요**: BIR_01(생년월일) 자체는 일반 의료기록 기본항목(A-021, 2026-07-29 확정)이라 이 동의와 무관하게 계속 수집 가능한지, 아니면 이 화면 스펙이 §22 전체를 "명리 목적"으로 프레이밍하고 있어서 BIR_01도 동의 대상에 넣어야 하는지 — 화면 문구가 출생"시간"만 언급하므로 **BIR_01(날짜)은 동의 대상 아니고 BIR_02~04(시간 관련)만 대상**으로 구현 권장. 다른 해석 필요하면 확인 요청.

### 데이터 저장 요구사항

- `birth_time_consent` 값·타임스탬프 별도 저장(단순 분기용 임시값 아님 — 동의 증빙 자료).
- 비동의 로깅과 "출생시간 모름(unknown)" 로깅은 다른 값으로 구분 저장(사유가 다름 — 하나는 거부, 하나는 정보 없음).

## 2. REC_01 — 진료 중 녹음 동의 (신규 섹션)

**배치 위치 확정(2026-08-09)**: §23 SUBMIT(`END_01`) 바로 앞, 독립 화면. 이유 — 문진 초반은 아직 진료 맥락이 없어 "녹음할게요"가 뜬금없고, 문진을 다 채운 뒤 "이제 상담 들어간다"는 흐름에서 자연스럽게 이어짐. BIR 섹션(명리 목적)과 주제가 다르므로 §22와 붙이지 않고 문진 종료 직전 별도 화면으로 배치.

문구:

> 더 정확히 기록하려고 오늘 상담을 녹음합니다. 원치 않으시면 말씀해 주세요.

variable:
`recording_consent`

input:
button (2지선다)

options:

| label | value |
|---|---|
| 동의 | agree |
| 비동의 | disagree |

required:
Y

### 운영 연동 — 반드시 확인

녹음 프로그램은 원장 컴퓨터 로컬 실행이며 이 태블릿 앱과 **기술적으로 연동돼 있지 않음**. `recording_consent = disagree`를 받아도 시스템이 자동으로 녹음 시작을 막지 못한다. 앱 차원에서 할 수 있는 것은:

- 동의값을 명확히 저장하고, 원장이 진료 시작 전 확인할 수 있는 화면(예: 접수 알림·요약 화면)에 크게 표시
- 그 이상(실제 녹음 차단)은 앱 범위 밖 — 절차적으로 원장이 녹음 버튼 누르기 전 이 값을 확인하는 운영 규칙으로 메워야 함(오케스트레이터가 별도로 운영 절차에 반영 예정)

### 데이터 저장 요구사항

- `recording_consent` 값·타임스탬프 저장(동의 증빙 자료, BIR_00과 동일 원칙).

## 4. Doctor 화면 연동 — 재진 지원 (신규 요구사항, 2026-08-09)

이 문서 범위 밖(Doctor 화면은 별도 시스템)이지만 태블릿 문진 데이터 흐름과 연결되므로 기록:

- 명리 계산 결과(오행 과다·부족 + 한열조습)는 **초진 시 1회 계산 후 환자 기록에 저장**, 재진에서는 재계산 없이 저장값 조회.
- 저장 위치는 EMR급 취급(차트번호 연결, 이름 없이) — `data-privacy.md` "원장 직접 운영 EMR급 DB"와 동일 분류. AI 경영실 저장소·이 questionnaire 리포지토리엔 계산결과 저장하지 않음.
- Doctor 화면 자체 구현은 별도 시스템(어디에 둘지 미정) — 이 문서는 요구사항만 기록.
