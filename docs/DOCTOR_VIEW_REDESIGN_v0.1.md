## 1. 현재 UI의 가장 큰 문제 10개

1. **행동이 가장 멀리 있다.** 원장이 오늘 해야 할 일(판단 입력, 진찰 소견, EMR 복사)이
   화면 맨 아래에 있다. 20개 섹션을 스크롤해야 "기록" 버튼에 닿는다.
2. **모든 섹션이 같은 시각 무게.** `doctor__section` 하나의 패턴이 환자 기본부터 원본
   JSON까지 동일하게 반복된다. 눈이 어디서 멈춰야 하는지 화면이 알려주지 않는다.
3. **안전 패널 최대 10개가 동일 칩 패턴으로 스택.** LBP/Hip/Neck/Shoulder/Knee/Elbow/
   WristHand/AnkleFoot/TMJ 패널이 각각 제목+칩열+노트+검사목록 구조를 반복한다.
   neck_shoulder 환자는 Neck+Shoulder 두 패널, arm_hand 환자는 Elbow+WristHand 두 패널이
   떠서 같은 정보 모양이 두 번 보인다. "무엇이 문제인지"보다 "패널이 몇 개인지"가 먼저 보인다.
4. **항상 빈 legacy 섹션.** "동반문제"는 새 문진에서 구조적으로 항상 비어 있는데
   섹션 제목 + 하위호환 설명문 + "동반문제 없음"까지 3줄을 매번 차지한다.
   "추가 상세상담 없음", "참고 증상 없음"도 각각 섹션 하나씩을 소비한다.
5. **타이포 위계 압축.** 값 14px, 라벨 12px, 섹션 제목 15px, 서브 제목 13px —
   전부 12~15px 안에 있다. 위계를 uppercase와 회색으로만 만들다 보니
   "작은 회색 글씨가 많은 화면"이 됐다.
6. **10초 요약이 10초 요약이 아니다.** TenSecondSummary는 좋은 시도지만 칩 6개가
   같은 크기·같은 색 상자로 나열되어 주호소와 명리 계산 상태가 동일한 무게다.
   환자 이름은 여기 없고(리스트에서만 보임) 상세 화면 어디에도 크게 표시되지 않는다.
7. **상세 증상 원시 나열.** Pain 환자는 PAIN + LBP(14) + HIP(8) 또는 NECK(15)+SHOULDER(11)
   필드가 2열 그리드에 라벨-값으로 전부 나열된다. 임상적으로 유의미한 양성 응답과
   "없음/해당없음" 응답이 같은 밀도로 섞인다.
8. **명리 검토가 중간에 크게 자리.** 3열 비교 그리드(원본→계산→문진 요약)는 감사(audit)
   용도로는 훌륭하지만 매 진료마다 펼쳐져 있을 필요가 없다. MyungriCompactCard와
   명리 검토 섹션이 사실상 같은 정보를 두 번 보여준다.
9. **desktop/tablet 레이아웃 부재.** max-width 1080px 단일 컬럼. 1440×900에서 좌우가
   놀고, 핵심 진료 영역이 세로로 3~4 viewport를 넘는다. 태블릿 대응은 900px에서
   화살표 숨기는 media query 하나뿐이다.
10. **저장 상태·데이터 신선도 표시가 약하다.** "기록" 성공 여부는 버튼 아래 JSON details로
    확인해야 하고, fixtures 모드의 "저장 안 됨" 경고는 본문 속 문장이다. 진료 중
    여러 번 드나드는 사용 패턴에서 "지금 저장돼 있나?"에 즉답하는 UI가 없다.

## 2. 유지해야 할 좋은 점

- **Provenance 3분류가 이미 데이터에 있다.** 환자 보고 / 시스템 계산(파생) / 원장 입력이
  코드 레벨에서 엄격히 분리되어 있고 UI 문구도 이를 지킨다("시스템이 계산한 것 — 출처",
  "원장이 직접 입력한 판단입니다"). 재설계는 이 구분을 시각 언어로 승격만 하면 된다.
- **"빈 값은 줄을 만들지 않는다" 원칙** (Field 컴포넌트). none/unknown 응답과
  "안 물어봄"의 구분(muted 처리)도 임상적으로 옳다 — 그대로 계승.
- **안전 우선 섹션 순서 불변식** (sectionOrder.ts + node 테스트). 안전 배너·약물병력이
  명리보다 항상 먼저 — 새 IA에서도 보존하고 테스트도 새 순서로 갱신한다.
- **fail-closed 안전 잠금 문구** ("안전 확인 전까지 운동/치료 추천은 잠깁니다") —
  임상 안전 장치이므로 문구 의미 그대로 유지.
- **위험신호 중복 회피 설계** (배너에서 전체를 보여주면 SafetyGlance는 포인터만).
- **EMR 복사 플로우** (seed → 편집 보존 → 수동 재조립 escape hatch)의 동작 계약.
- **참고 증상은 진단처럼 보이면 안 된다**는 §19/§23 규칙 — muted 처리 유지.

## 3. 과감히 제거/축소할 요소

| 대상 | 처리 | 근거 |
|---|---|---|
| legacy "동반문제" 섹션 | **데이터가 있을 때만 렌더** (섹션 자체 생성 안 함) | 새 문진에서 항상 빈 구조 |
| "추가 상세상담 없음"/"참고 증상 없음" 빈 섹션 | 섹션 제거, 있을 때만 "그 외 호소" 블록에 통합 | 빈 상태가 공간 소비 |
| 원본 JSON details | Level 4 (도구 메뉴 속 "원본 데이터") | 개발자 도구 성격 |
| MyungriCompactCard + 명리 검토 이중화 | compact 카드 하나로 통합, 3열 감사 뷰는 펼치기 | 같은 정보 2회 노출 |
| 헤더의 데이터 소스/fixture 픽커 | 도구(⚙) 메뉴로 이동 | 운영 도구가 진료 화면 상단 점유 |
| 안전 패널 10종의 개별 섹션 | 통합 "안전 확인" 모듈 1개로 병합 (§8) | 반복 패턴 제거 |
| 환자 기본 8필드 그리드 | 헤더로 3개 승격(이름·성별/나이·차트번호), 나머지는 참고 접기 | 기본 정보가 섹션 하나를 차지할 이유 없음 |
| 진료 워크스테이션 배지·모드 배지 | 상단바 우측 meta 영역으로 축소 | 운영 메타데이터 |

## 4. 새 정보 구조 (4-Level Hierarchy)

**Level 1 — 즉시 (진입 후 3~5초):** 환자 헤더 밴드
- 환자명 + 차트번호(또는 휴대폰 끝 4자리) + 성별/나이
- 주호소(가장 큰 텍스트) + 기간·빈도 한 줄
- 안전 상태 종합 pill 1개: `긴급 확인` / `확인 필요 n건` / `안전 확인됨`
- 직전 방문 대비 변화 슬롯 (재진 데이터 있을 때만 — §13 invariant 참고)
- 오늘 확인할 것 카운트 (→ 우측 레일 앵커)

**Level 2 — 오늘 판단의 근거:** 좌측 컬럼
- 통합 안전 확인 (모든 모듈 안전 상태 + 위험신호 + 잠금 상태)
- 문진 핵심 (양성/유의미 응답 우선 표시, 전체 원시 응답은 펼치기)
- 복용약·병력·알레르기·수술 / 임신·수유 파생 사실

**Level 3 — 오늘 입력:** 우측 레일 (sticky)
- 오늘 확인 체크리스트 (추가 권장 검사 통합 + 진찰 소견 radio 입력)
- 원장 판단 기록 (compact 폼)
- EMR 요약·복사
- 저장 상태 인디케이터

**Level 4 — 참고 (한 번의 명확한 action으로 접근):**
- 명리 3열 감사 뷰, 전신·한약 참고 전체, 원시 module 응답 전체,
  transcript 원문, 원본 JSON, legacy 동반문제(존재 시)

## 5. 레이아웃 후보 3안

### Option A — Clinical Summary + Action Rail
좌 7/12: 상태·근거 (읽기) / 우 5/12 sticky: 확인·입력·EMR (쓰기).
상단 전폭: 환자 헤더 밴드. 위험 배너는 헤더 바로 아래 전폭.

### Option B — Timeline + Current Visit
상단: 방문 요약 밴드 / 중앙: 오늘 판단·처치 / 하단 또는 좌측 얇은 rail: 이전 방문 타임라인.

### Option C — Progressive Clinical Cockpit
첫 화면: 요약+위험+변화+오늘 액션 4카드만. 근거·상세·기록은 전부 클릭 확장.

## 6. 후보별 장단점

| 기준 | A | B | C |
|---|---|---|---|
| 10초 가독성 | ◎ 읽기/쓰기 공간 분리로 scan path 고정 | ○ 요약은 좋으나 근거가 아래로 밀림 | ◎ 첫 화면 밀도 최소 |
| 입력 부담 | ◎ 입력이 항상 화면에 있음 | ○ 중앙 입력이지만 근거와 시선 왕복 | △ 입력까지 클릭 1회 추가 |
| 위험/모순 인지 | ◎ 전폭 배너 + 헤더 pill | ○ | ○ 단 확장 전 근거 안 보임 |
| 스크롤 최소화 | ◎ 양 컬럼 독립 스크롤 | △ 세로 흐름 유지 | ◎ 단 확장 시 오히려 증가 |
| 이전 방문 변화 | ○ 헤더 슬롯 | ◎ 타임라인이 1급 시민 | ○ |
| 태블릿 1024 | ○ 레일 하단 결합 필요 | ○ | ◎ 카드형이 터치 친화 |
| 구현 현실성(비제약) | ○ | △ 방문 이력 데이터 모델 선행 필요 | ○ |
| 임상 안전성 | ◎ 안전이 항상 좌상단 고정 | ○ | △ 접힌 근거 뒤 안전정보 누락 위험 |

### 판정
- **B 탈락**: 타임라인을 1급으로 만들기엔 재진(이력) 데이터 모델이 아직 payload에 없다.
  "구현에 맞추기 쉬운 안"이 아니라 임상 사용성 기준으로도, 초진 위주 현 단계에서
  타임라인이 빈 화면의 중심이 되는 것은 손해다.
- **C 탈락**: 확장 전에는 안전 근거가 안 보인다는 점이 임상 안전성 목표(§2-3)와 충돌.
  "펼쳤다 접기" 행동 비용도 §7 인터랙션 원칙과 어긋난다.

## 7. 최종 추천안 — **Option A + C의 progressive disclosure**

Option A의 2-컬럼 cockpit을 뼈대로, Level 2 내부의 상세(원시 응답 전체·명리 감사 뷰)만
C 방식의 확장으로 숨긴다. 근거의 *요약*은 항상 보이고, 근거의 *원문*은 한 번의 확장으로
접근한다 — "요약은 즉시, 원문은 1클릭" 원칙.

## 9. Visual Design System

### 9.1 Layout Grid
- 콘텐츠 max-width 1320px, 12-col, gutter 24px, 좌우 여백 32px.
- 좌 컬럼 7col / 우 레일 5col (1440). 1280 미만: 6/6. 1024: §8.2.
- 세로 리듬: 섹션 간 32px, 블록 내 16px, 필드 간 8px.

### 9.2 Spacing Scale
`4 / 8 / 12 / 16 / 24 / 32 / 48` — 이 7단계 외 임의 값 금지.

### 9.3 Typography Scale (Pretendard 유지)
| 역할 | 크기/무게 | 용도 |
|---|---|---|
| Display | 22px / 700 | 환자명 |
| Title | 18px / 700 | 주호소, 레일 블록 제목 |
| Section | 14px / 650 | 좌측 섹션 제목 (uppercase 제거) |
| Body | 15px / 500 | 데이터 값 (기본) |
| Body-strong | 15px / 700 | 유의미 양성 값 |
| Label | 12px / 500 | 데이터 라벨, muted |
| Meta | 12px / 400 | 시각·출처·상태 문구 |

원칙: **회색을 줄이고 무게로 위계를 만든다.** muted는 라벨·meta·none 응답에만.

### 9.4 Color Roles
| 토큰 | 값(제안) | 역할 |
|---|---|---|
| `--bg` | #FAFAF8 | 페이지 배경 (중성, 살짝 warm) |
| `--surface` | #FFFFFF | 카드/레일 표면 |
| `--text` | #1A1F1C | 본문 (contrast ≥ 12:1) |
| `--text-muted` | #6B7370 | 라벨/meta 전용 |
| `--green` | #1E6B4F | primary action, 선택 상태, 저장됨 |
| `--mint` | #DDF0E7 | positive/완료 배경 (배경으로만) |
| `--amber` | #8A6D23 / #F3EAD2 | REVIEW_REQUIRED, stale/정책 대기 |
| `--red` | #B3261E / #F6ECE9 | URGENT_REVIEW, 위험신호만 |
| `--clinician` | green 4px left-border | **원장 입력 데이터 표식** |

색 사용 규칙: 브랜드 green은 행동(버튼·선택·저장)과 원장 입력 표식에만.
정보 위계는 typography→spacing→grouping이 먼저, 색은 마지막.

### 9.5 Card/Border 원칙
- **카드는 3종만**: ① 우측 레일 블록(surface+shadow-sm) ② 경고 밴드(red/amber bg)
  ③ 직전 방문 비교 칩. 그 외 좌측 섹션은 **카드 없이 제목+whitespace로 구분**.
- border는 리스트 내부 1px divider만. 섹션 외곽 박스 금지.
- radius 8px 단일값(경고 밴드 6px).

### 9.6 Provenance 시각 언어 (임상 요구 §11)
| 출처 | 표식 |
|---|---|
| 환자 보고 | 기본 스타일 + 라벨에 자동 표기 없음 (기본값) |
| 시스템 계산(파생) | 라벨 앞 `계산` 12px 태그 (mint bg) + 출처 문구 유지 |
| 원장 입력 | 좌측 4px green border + "원장 입력" 태그 |
| 안 물어봄 | 렌더 안 함 (현행 유지) |
| none/unknown 응답 | muted italic (현행 유지) |

## 11. Interaction Specification

### 11.1 상태별 동작
| 상태 | 동작 |
|---|---|
| 로딩(목록/상세) | 스켈레톤(헤더+좌 2블록+레일 1블록), 스피너 금지 |
| 서버 오류 | 상단바 아래 amber 스트립 + "다시 시도" — 화면 전체 차단 금지 |
| auth 오류 | 기존 DoctorTokenSetup 플로우 유지, 레일 영역에 표시 |
| 빈 값 | 줄 생성 안 함(현행). 섹션 전체가 비면 섹션도 생성 안 함 |
| 미확인(unknown) | muted + "오늘 확인" 체크리스트에 자동 집계 |
| 저장 성공 | 레일 인디케이터 `저장됨 · n분 전` (green dot), 버튼 옆 상주 |
| 저장 실패/미저장 | amber dot + `저장 안 됨` + 재시도. fixtures 모드: `미리보기 — 저장되지 않음` 상주 배지 |
| stale (정책 대기 등) | amber 인라인 스트립 — 현행 문구 유지, 공포감 없는 톤 |
| 새 recorder 결과 도착 | 현행 토스트 유지하되 레일 EMR 블록에 green dot 동기화 |

### 11.2 행동 비용 절감
- 진찰 소견(LBP motor deficit / Shoulder cuff weakness)은 **레일 "오늘 확인" 안의
  radio 한 줄** — 판단 폼을 열지 않고 바로 입력.
- "오늘 확인" 체크리스트 = 추가 권장 검사(모듈별 통합) + 미확인 항목(수술력 종류,
  free text, 기타 선택) 자동 집계. 체크는 로컬 UI 상태(임상 기록 아님 — 저장 계약 변경 없음).
- 판단 폼: 핵심 2필드(선천 특징·증상 연결)만 기본 노출, 4 textarea는 현행처럼 접기.
  keyboard: Tab 순서 = 레일 위→아래, `Cmd/Ctrl+Enter` = 기록.
- 같은 값 재입력 금지: 저장된 judgment 재열람 시 폼 프리필(현행 유지) + 레일 상단에
  "이전 기록 있음 · n시간 전" 표시.

### 11.3 안전 통합 모듈 상세 (좌측 ◆안전 확인)
- 한 줄 = 한 부위: `부위명 [상태 pill] 핵심 플래그 요약 ▸`
- 상태 pill: URGENT(red)/확인 필요(amber)/안전(mint) — 현행 3-status 그대로 매핑.
- 행 확장 시: 해당 모듈의 플래그 상세 + 잠금 문구 + 권장 검사(레일 체크리스트와 동일
  데이터, 여기선 읽기 전용 목록).
- URGENT가 하나라도 있으면 해당 행을 자동 확장 + 헤더 pill을 `긴급 확인`으로.
- 잠금 문구(fail-closed)는 상태 pill 옆 자물쇠 아이콘 + 문구 그대로 — 축약 금지.

## 13. 구현 시 반드시 지켜야 할 Invariant

1. FROZEN: `src/spec/*Logic.ts`, `src/spec/*Adapter.ts` — 호출 방식·게이트 조건
   (`safety_flags.* !== null`, `primary_location` 게이트) 변경 금지. **UI 재구성은
   렌더 계층에서만.**
2. 안전 정보가 명리·참고보다 항상 먼저 — sectionOrder 테스트를 새 순서로 갱신하되
   불변식 자체는 유지.
3. 잠금(fail-closed) 문구의 임상 의미 축약·완화 금지.
4. "안 물어봄 ≠ 없음 응답" 구분 유지 (Field 규칙).
5. 원장 입력은 자동 채움·자동 추천 금지 — 체크리스트 체크 상태는 저장 계약에 넣지 않음
   (로컬 UI 상태로만).
6. 진찰 소견 radio(LBP/Shoulder)는 기존 judgment 저장 경로 그대로 — 별도 저장 메커니즘
   신설 금지.
7. identity: 환자명+차트번호 표시. RRN·전화번호 identity key 사용 금지(끝 4자리는
   표시용 보조). 자동 병합 없음.
8. 직전 방문 비교는 **데이터가 실제 존재할 때만** 렌더 — 새 임상 threshold·해석 생성 금지,
   원시 값 나란히 표시만.
9. 참고 증상·기타 확인은 urgent보다 강조 금지 (§19/§23 현행 규칙).
10. 환자 개인정보를 이 문서 포함 어디에도 실제 값으로 기록하지 않음.

## 14. 구현 순서 (디자인 승인 후)

1. **P1 — 골격**: 2-컬럼 grid + Patient Header + 상단바. sectionOrder 갱신+테스트.
2. **P2 — 안전 통합 모듈**: 10개 패널 → 통합 리스트 (로직 호출 그대로, 렌더만 병합).
3. **P3 — 우측 레일**: 오늘 확인 체크리스트 + JudgmentPanel compact 재배치 + 저장
   인디케이터 + EMR 블록 이동.
4. **P4 — 문진 핵심**: 유의미 응답 우선 정렬 + 원시 전체 펼치기.
5. **P5 — 참고 접기**: 명리 통합·전신한약·원본 데이터.
6. **P6 — 반응형**: 1024 action bar + 터치 타겟.
7. **P7 — 상태·마감**: 스켈레톤, 저장 상태, 토큰/워크스테이션 플로우 재배치, QA.
