# 목(NECK) 운동 파일럿 — 원장 관찰 로그 v1.0

**상태**: 파일럿 진행 중 (시작 2026-09-07). 정본 결정은 `docs/NECK_EXERCISE_DECISIONS_v1.0_CLOSED.md`(§10이 관찰 7항목).
**전제**: 목 팩은 **B수준 근거 확인으로 production에 들어간다** — 요통 팩과 같은 기준
(`DECISIONS.md` 2026-09-07 "검증 수준 정책"). 원문(A수준) 대조는 파일럿 전제조건이 아니라 v1.1 항목이다(§4-2).
**이 문서의 역할**: 원장이 파일럿 동안 **무엇을 기록해야 집계가 되는지**, **어떤 숫자가 나오면 v1.1을 여는지**를 한 장에 둔다.

---

## 1. 원장이 진료 중 하는 일 (환자 1명당, 추가 30초)

자동 집계(§2)는 원장 화면에 **저장된 값**만 센다. 아래 세 가지를 기록하지 않으면 그 환자는 "미시행/미기록"으로 집계된다
— 그것도 데이터지만, 첫 라운드는 아래를 지켜야 §3의 판정이 의미를 가진다.

| # | 원장 화면에서 | 어디에 | 집계 항목 |
|---|---|---|---|
| a | 신경 검사 2개(`C5–T1 신경학적 기준선`, `UMN 징후`)의 결과를 **NEGATIVE/POSITIVE/기타** 중 하나로 기록 | 검사 카드 | ③ |
| b | 방향성 반응(굴곡 호전 / 신전 호전 / 뚜렷한 방향 없음 / 원위부 악화)을 기록. 시행하지 않았으면 그대로 둔다(미시행으로 집계) | 방향성 카드 | ② |
| c | 후보 운동 카드마다 **채택 / 보류 / 배제** 중 하나를 누른다. 안 누르면 "미결"로 남는다 | 운동 후보 카드 | ⑦ |
| d | 재진 재질문(세부문진)을 평소대로 발급한다 — `NECK_12`(지속 자세 내성)가 자동으로 포함된다 | 재질문 발급 | ⑤ |

단계(④)는 문진 답변으로 자동 계산되므로 원장이 할 일이 없다.

## 2. 집계 명령 (원장 PC, 언제든 반복 실행 가능)

```bash
npm run pilot:region-observation -- neck
# 데이터 폴더가 다르면
SAMINDANG_DATA_DIR=D:\경로\submissions npm run pilot:region-observation -- neck
```

- 환자를 새로 모집하지 않고, 이미 저장된 제출 기록과 재질문 응답만 읽는다. 클라우드 세션에서는 돌지 않는다(환자 기록이 없다).
- 이름·전화·생년월일·자유서술·메모는 **읽지 않는다**. 세는 것은 선택지 코드값·검사 상태·운동 id·채택 상태뿐이다
  (`tests/region-pilot-observation.spec.mjs`가 강제).
- 스크립트: `scripts/region-pilot-observation.mjs` — 부위 무관. 신경 검사 id·운동 목록·방향성 조건은 팩에서, 재질문 id는 서버 표에서 읽는다.

### 출력 블록 ↔ CLOSED §10 항목

| 출력 블록 | §10 항목 | 무엇을 세는가 |
|---|---|---|
| `② 방향성 반응` | 2 | 저장된 기록 중 굴곡/신전/방향 없음/원위 악화/미시행 건수 |
| `③ 신경 검사 기록` | 3 | 두 검사 **모두** 기록된 건수, 하나도 안 된 건수, POSITIVE(운동 차단) 건수 |
| `⑦ 운동 후보 채택` | 7 | Core 9 각 운동이 후보로 뜬 건수와 채택/보류/배제/미결. `NECK_DIR_01` 행에 "방향성 조건부" 비고 |
| `⑤ 재질문 응답` | 5 | 목 방문에 연결된 재질문 응답 수, 그중 `NECK_12` 답변이 있는 수 |
| `목 운동 단계 — 회고 파일럿 분포` | 4 | 기존 `pilot:region-stage -- neck` 본체를 이어서 실행 |
| (없음 — §4 표에 손으로) | 1, 6 | 카드 문장 수정, 원문 대조 |

**분모**: ②③⑦은 "원장 화면이 저장된 목 기록", ⑤는 "목 제출 전체"(재질문이 발급되지 않은 방문도 포함된 거친 비율)다. 출력이 분모를 명시한다.

## 3. 판정 임계값 — 제안값 (이 숫자가 나오면 v1.1에서 그 항목을 다시 본다)

임상 임계값이 아니다. "회의를 여는 기준"이며 스크립트 `THRESHOLDS`와 테스트가 같은 숫자를 고정한다. 바꾸려면 셋을 같이 바꾼다.

| 신호 | 기준 | 뜻 / v1.1 행동 |
|---|---|---|
| 저장된 목 기록 수 | < 10건 | 모든 비율은 방향 참고용. 첫 라운드 종료 기준(§5) 미달. |
| 원장 화면 저장 비율 | < 80% | 열지 않았거나 저장되지 않은 목 제출이 많다 → §1 절차 재확인(코드 문제 아님). |
| 굴곡 호전 비율(방향성 기록 중) | ≥ 20% | v1.0에는 굴곡 호전형 후보가 없다(CLOSED §3 보류 `NECK_DIR_02`) → **DIR_02 추가 검토**. |
| 신경 검사 2개 모두 기록 비율 | < 70% | 미기록 안내문이 검사를 유도하지 못한다 → 문구·위치 수정(팩 아님, 화면). |
| `NECK_DIR_01` 채택률 | 후보 ≥ 5건이고 채택 < 20% | 근거 제한(로그 §2-4) + 실제 채택 낮음 → **v1.1 유지/삭제 결정**. 채택률이 높으면 유지 근거. |
| `NECK_12` 답변 비율(목 제출 대비) | < 50% | 재질문 발급·응답 경로 확인. 문항 자체 문제인지, 발급 누락인지는 원장이 구분. |
| 단계 분포 | 0단계 > 30% / 한 단계 > 80% / 판단 불가 > 10% | 기존 회고 파일럿 기준 그대로(`LBP_EXERCISE_STAGE_ASSIGNMENT_v0.4.md` §5). |

## 4. 손으로 적는 항목

### 4-1. 카드 문장 수정 (§10-1) — 파일럿 중 발견 즉시

7필드 문장은 Claude 초안이 PO 위임으로 확정된 것이다(CLOSED 머리말). 환자 앞에서 읽다가 어색하거나 틀린 문장을 여기 적는다.
팩 파일(`regionPacks/neck.ts`)의 해당 문자열을 고치는 것은 v1.1 커밋에서 한꺼번에 한다.

| 날짜 | 운동 id | 필드 (startingCriteria / startingDose / acceptableResponse / stopReview / regression / progression / strategyLabel) | 현재 문장 | 수정 문장 |
|---|---|---|---|---|
| | | | | |

### 4-2. A수준 원문 대조 (§10-6) — v1.1 항목, 파일럿 전제조건 아님

`docs/REHAB_REFERENCE_VERIFICATION_LOG_v0.1.md` §5의 5건. 요통 팩도 이 단계 없이 production에 들어갔으므로 목만 요구하지 않는다.
원문을 볼 기회가 있을 때 한 줄씩 채운다. **원문이 B수준 요약과 다르면** 그 행만 CLOSED v1.1 재개방 사유가 된다.

## 5. 첫 라운드 종료와 v1.1 재개방

**종료 기준(둘 중 먼저)**: 원장 화면이 저장된 목 기록 **10건** 또는 **4주**.

종료 시:
1. `npm run pilot:region-observation -- neck` 출력 전체를 이 문서 §6에 붙인다(숫자만 있으므로 개인정보 없음).
2. §4-1 표의 문장 수정 목록.
3. §3에서 발동한 신호마다 결정 1줄(유지 / 변경 / 데이터 더 필요).

v1.1 재개방 = `DECISIONS.md` 항목 1개 + `NECK_EXERCISE_DECISIONS_v1.1.md`(변경 행만) + 팩 변경 시 `tests/neck-exercise-core.vignettes.spec.mjs` 갱신.
문장만 바뀌면 비네트 갱신은 필요 없다(비네트는 id·규칙·단계만 단언한다).

어깨 ②(`docs/SHOULDER_EXERCISE_EVIDENCE_MATRIX_v0.1.md` §10)는 이 첫 라운드 종료 후 착수한다 — 같은 단계 축(VISIT_04)을 두 부위가
동시에 처음 쓰면 어느 쪽 문제인지 구분이 안 된다. PO가 "지금"을 택하면 즉시 가능.
