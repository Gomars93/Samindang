# 요통 운동 단계 배정 v0.4 — 격하 모델 전환 + 0단계 신설

**상태**: 규칙 구현·검증 완료, **화면 배선 전**, 회고 파일럿 대기.
**v0.3을 대체한다** — v0.3의 결정 B(점수척도)·C(원장 주도형 통합판단)는
그대로 유효하고, 바뀐 것은 결정 A(단계 배정 규칙)뿐이다.
**앞선 문서**: `LBP_EXERCISE_STAGE_ASSIGNMENT_v0.3.md`,
`LBP_EXERCISE_LEVEL_DRAFT_v0.2.md`(운동 20개의 단계).

## 0. v0.3에서 무엇이 왜 바뀌었나

2026-09-05 원장 검토에서 두 가지 지시가 나왔고, 그 결과 **상한(CAP) 모델을
격하(DEMOTION) 모델로 바꾸고 0단계를 신설**했다.

### 지시 1 — "급성 심한 케이스는 1단계도 힘들 수 있다"

> "급성 요통 심한 케이스 2단계도 힘든지 바로 1단계지. 1단계도 힘들 수 있어.
> 근육 락킹으로 신경계를 보호하려고 하잖아. 누워있는 게 치료라고 입버릇처럼
> 말하는데."

이 지시에는 **오해 1개와 진짜 결함 1개**가 섞여 있었고, 둘 다 확인했다.

- **오해**: v0.3에서도 `severe + 발병 1주 이내`는 **이미 1단계**였다. 상한은
  "그 이상으로 올리지 마라"는 연산이라 기본 단계가 이미 1이면 발동하지
  않는다. 상한 2단계가 실제로 한 일은 "거의 안 아픈데 발병 3일차인 환자를
  3단계로 보내지 마라" 하나뿐이었다.
- **진짜 결함**: **0단계가 없었다.** v0.3의 최소 단계는 1단계였고, 1단계는
  "운동 20개 중 9개를 처방한다"는 뜻이다. protective muscle guarding 상태에
  능동 운동을 얹지 않는다는 선택지가 시스템에 존재하지 않았다. TBC 3단계를
  그대로 가져오면서 그 아래를 비워둔 설계 실수다.

### 지시 2 — "재발 간격 3개월이면 1단계씩 격하"

> "재발 간격이 3개월이면 조심해야지, 1단계씩 격하시켜야지."

규칙 자체는 명확했으나 **입력이 없었다**. `LBP_07`은 "이전에도 있었나요?"만
묻고 *언제*를 묻지 않는다. 그래서 문항 `LBP_07B`를 신설했다(아래 §2).

### 전환의 실제 이점

두 지시 모두 **"한 단계 낮춘다"**는 같은 연산이다. 상한 모델을 유지한 채
"severe+급성은 0단계" 규칙을 따로 붙이면 규칙이 4종류가 되고 원장이 결과를
예측할 수 없다. 격하 모델로 통일하면 **산술 하나로 전부 나온다.**

---

## 1. 확정 규칙 (v0.4)

```
기본 단계  = 일상생활 지장도(VISIT_04)
             severe → 1 / moderate → 2 / mild·minimal → 3

격하(-1, 누적)
  · 발병 1주 이내 (VISIT_03 = within_1w)
  · 3개월 이내 재발 (LBP_07B = within_3m)      ← v0.4 신규

상한(누적 안 됨)
  · 공포회피 뚜렷 (LBP_13 = YES) → 최대 2단계

최종 = clamp(기본 − 격하 개수, 0, 3) 에 상한 적용
```

**기본 단계는 0이 될 수 없다.** 0단계는 격하로만 도달한다 — "일상생활이
어렵다"는 답 하나만으로 운동을 끊지는 않는다는 뜻이다.

### v0.3 대비 결과가 바뀌는 지점

| 일상지장도 | 발병 1주 이내 | v0.3 (상한) | **v0.4 (격하)** |
|---|---|---|---|
| severe | 예 | 1단계 | **0단계** |
| moderate | 예 | 2단계 | **1단계** |
| mild | 예 | 2단계 | 2단계 |
| minimal | 예 | 2단계 | 2단계 |

재발 격하는 v0.4 신규이므로 v0.3 대비 전 구간이 신규다.

### 격하가 누적된 예

| 지장도 | 급성 | 3개월내 재발 | 계산 | 최종 |
|---|---|---|---|---|
| severe | 예 | 예 | 1 − 2 = −1 → 0 | 0단계 |
| moderate | 예 | 예 | 2 − 2 = 0 | 0단계 |
| mild | 예 | 예 | 3 − 2 = 1 | 1단계 |
| minimal | 아니오 | 예 | 3 − 1 = 2 | 2단계 |

## 2. 0단계 — 무엇을 하는 단계인가

**0단계 · 보호/안정.** "아무것도 안 한다"가 아니다.

> 오늘은 능동 운동을 처방하지 않습니다. 통증이 없는 자세(눕기·무릎 세우고
> 눕기)와 편안한 호흡, 통증 없는 범위의 자발적 움직임만 안내하고 다음
> 진료에서 다시 평가합니다.

(소스: `LBP_STAGE_0_GUIDANCE_KO`. 원장이 환자에게 그대로 말할 수 있는 문장이어야
한다는 제약을 두고 썼다.)

**화면 배선 시 필수 요구사항**: 0단계 제안 옆에 **"1단계로 올리기"를 한 번의
조작으로** 둔다. 안전한 쪽이 기본값이고, 올리는 것이 의식적 행위여야 한다.
내리는 쪽을 한 번의 조작으로 두면 방향이 거꾸로다.

### 근거의 한계 — 정직하게

TBC(Alrwaily 2016) 원문에 "0단계"는 없다. Stage I이 최저다. 0단계는
**삼인당의 정책 결정**이며, 근거는 다음 둘이다:

1. TBC Stage I의 정의는 "pain severely limits movement"라는 *상태 기술*이지
   "능동 운동을 시작한다"는 *처방 지시*가 아니다. 그 상태에서 무엇을 할지는
   원문이 정하지 않았다.
2. 급성기 protective muscle guarding에 능동 운동을 얹는 것의 이득이
   확립되어 있지 않다(WHO 2023 CPLBP의 운동 근거는 대부분 만성 대상).

**"0단계가 회복을 앞당긴다"는 근거는 없다.** 0단계가 주장하는 것은
"급성기에 운동을 처방하지 않는 선택지가 있어야 한다"까지다. 그 이상을
문서·화면 어디에도 쓰지 않는다.

## 3. 신규 문항 LBP_07B

```
LBP_07B  "마지막으로 그렇게 아팠던 게 언제인가요?"
  노출 조건: LBP_07 === 'YES' (즉 재발 환자에게만)
  required : false
  선택지   : 3개월 이내 / 3개월~1년 / 1년 이상 / 잘 모르겠어요
```

**왜 태블릿에 넣었나 (원장이 화면에서 클릭하지 않고)**: 이건 원장이 매번
기억해서 입력할 정보가 아니라 **환자만 아는 정보**다. 매 진료마다 구두로
묻는 것보다 태블릿이 묻는 편이 정확하고 빠르다. `LBP_07 = YES`인 환자에게만
나오므로 초진 대다수의 문진 길이는 변하지 않는다.

**격하 사유는 "재발 사실"이 아니라 "짧은 간격"이다.** `3m_1y`/`over_1y`는
격하하지 않는다. `unknown`과 미응답도 격하하지 않는다 — 없는 재발을
지어내지 않는다(모르면 안전한 쪽이 아니라 **중립**으로 둔다).

**옛 기록 호환**: 이 문항 도입 전 제출에는 `recurrence_interval`이 없고,
그 경우 재발 격하가 발동하지 않는다. 회고 파일럿 스크립트가 이 사실을
경고로 띄운다(§5).

## 4. 이 규칙이 여전히 하지 않는 것

v0.3에서 그대로 이어지는 제약. 전부 테스트가 소스 텍스트로 강제한다.

1. **확정하지 않는다** — 출력은 제안이고, 확정은 원장의 명시적 조작이다.
2. **이전 방문과 자동 비교하지 않는다** — `REPEAT_VISIT_AUTO_COMPARE_STATUS`
   원칙. 재진에서도 **오늘의 답변만** 본다.
3. **점수를 만들지 않는다** — 가중합·임계값·랭킹 없음.
4. **진단명을 쓰지 않는다.**

## 5. 회고 파일럿 — 다음에 할 일

**단위 테스트는 "규칙이 정해진 대로 작동하는가"만 본다. "그 규칙이 임상
현실과 맞는가"는 분포로만 알 수 있다.**

```bash
npm run pilot:lbp-stage
# 데이터 폴더가 다르면
SAMINDANG_DATA_DIR=D:\경로\submissions npm run pilot:lbp-stage
```

이미 받아둔 제출 기록에 규칙을 그대로 돌린다. **환자를 새로 모집하지 않고,
원장이 손으로 입력할 것도 없다.** 개인정보는 읽지도 출력하지도 않는다 —
세는 것은 선택지 코드값뿐이다(테스트가 강제).

### 실패 모드 — 이 숫자가 나오면 규칙을 다시 만든다

| 신호 | 기준 | 뜻 |
|---|---|---|
| 0단계 비율 | > 30% | 환자 3명 중 1명 이상이 운동을 못 받는다. 격하가 과하다. |
| 한 단계 쏠림 | > 80% | 단계를 나누는 의미가 없다. 배정 축을 다시 봐야 한다. |
| 판단 불가 | > 10% | VISIT_04 미응답이 많다. 문진 흐름 문제. |
| 판정 건수 | < 20건 | 분포를 신뢰할 수 없다. 방향 참고용으로만. |

스크립트가 이 판정을 자동으로 내린다. 임계값은
`tests/lbp-stage-pilot.spec.mjs`가 고정한다.

### 순서

1. **회고 파일럿** (환자 0명) ← 지금 여기
2. **최소 화면** (읽기 전용 제안 표시, 저장 없음)
3. **실환자 파일럿 5~10명** (원장 판단 vs 시스템 제안 대조)
4. **UI 확정 + 저장 배선**

1을 건너뛰고 3으로 가면, 분포가 이상하다는 걸 화면을 다 만든 뒤에 알게 된다.

원장 승인("너의 추천으로 모두 진행") 후 구현. 상세는 `DECISIONS.md` 같은 날짜
"준비조건 두 층" 항목과 `src/doctor/workspace/lbpCapabilityLayer.ts` 헤더.

| 층 | 조건 | 기본값 | 누가 정하나 |
|---|---|---|---|
| **A. 안전 금기 (3)** | `SAFE_WALKING`, `BALANCE_WITH_SUPPORT`, `CAN_SELF_PACE` | UNKNOWN (fail-closed 유지) | 원장이 반드시 직접 확인 |
| **C. 단계 추정 (12)** | 나머지 전부 | 확정 단계에서 추정 YES | 안 되는 것만 원장이 끔 |

- 제안했던 **B층(문진 유도)은 비어 있다** — 문진에 자세 수행 가능 여부 문항이

- 추정 문턱은 손으로 정하지 않고 **규칙표 × 단계표(v0.2)에서 계산**한다:
  1단계 확정 → 8개, 2단계 → 10개, 3단계 → 12개가 추정 YES.
- 우선순위: 확인함 > 지금은 안 됨 > 추정 > UNKNOWN. 원장이 누른 값이 항상 이긴다.
- **운동 단계 카드**(판단·처치 레인, 초진): 제안 + 0~3 버튼 + "제안대로 확정"

- 확정 단계보다 높은 운동은 후보에서 빠진다. 0단계면 후보 블록이 안내문으로 접힌다.
- 원장 최소 조작: **단계 1탭 + 신경 상태 1탭 + A층 최대 3탭** (이전 15탭+1).

남은 것: 재진 화면(운동 섹션 자체가 없음), EMR 출력(`emrPreview.ts` 파일럿 동결).

### 6.2 재발 환자를 별도 트랙으로 뺄 것인가 — **빼지 않기로**

격하 규칙 하나로 끝낸다. 트랙을 나누면 화면·저장 스키마·재진 비교·EMR
요약이 전부 2배가 되고, 이 저장소는 이미 초진/재진/한약 3갈래다
(CLAUDE.md의 "같은 사고가 네 번" 항목이 그 대가다).

**남는 한계(기록만)**: "3년째 반복되는 만성 재발"과 "작년에 한 번 삐끗"이
같은 취급을 받는다. 이건 격하가 아니라 **운동 종류 선택**에서 다룰 문제이고
단계 시스템의 일이 아니다.

### 6.3 그 밖

- 단계 **상승** 기준 — 재진에서 무엇을 보고 올리는가. TBC 원문에도 명시
  기준이 없다(v0.2 §다음 참고).
- `LBP_12`(회복 기대)·`LBP_14`(업무 지장)는 계속 참고 문장으로만 둔다.
