## 결론 먼저

1. **이 세션(클라우드)에서는 원서 본문에 도달할 수 있는 경로가 없다.** 상·하권 모두
   Drive 커넥터가 **0바이트**를 돌려주고, 컨테이너는 `drive.google.com` 에 접속할 수 없으며,
   `notebooklm` MCP 는 로컬 Windows 전용이라 실행되지 않는다. 따라서 **상·하권 전수 ingestion 은
   이 환경에서 수행 불가**다. 실행은 원서와 vault 가 같이 있는 로컬 PC 에서 해야 한다.
2. 그래서 이번 세션의 산출물은 "일부 약재만 처리한 중간본"이 아니라
   **로컬에서 전수 실행할 수 있는 재현 가능한 툴체인 + 회귀 테스트 + 현재 KB 실사**다.
3. **현재 KB 는 "전수처리 완료"와 거리가 멀다.** 상권 0건, 하권 125건이며, 그중 33건은
   원서 범위가 확보되지 않은 수기 stub 이고, 99건이 `ocr_uncertain: true` 다.
4. 가장 시급한 구조적 결함은 **broken wikilink 93건(장 전체 원문 note 12종이 아예 없음)** 과
   **안전성 색인 8종 전부 부재**다. 현재 상태로 다른 AI 에 물리면 안전성 축에서 검색이
   빈손으로 끝난다.

### 2.2 provenance 불일치 — 확인이 필요한 사항

`운곡본초학_논리분할_MANIFEST` 는 하권 845면을 100면 단위 9개 chunk 로 나눠놓고
**H-01 PENDING / H-02 (101–200) IN_PROGRESS / H-03~H-09 PENDING** 로 기록하며,
"검수 포인트"로 실제 확인된 면은 **PDF p.180–181 두 면뿐**이다.
그런데 A세대 93개 note 는 **PDF p.173–681** 을 인용한다.

두 기록은 양립하지 않는다. 둘 중 하나다.
(a) 실제로 전 범위를 읽었고 MANIFEST 갱신이 누락됐다, 또는
(b) 일부 note 의 페이지 범위가 실제 확인된 것이 아니다.

**추측하지 않는다.** 로컬에서 `ungok_extract.py` 로 캐시를 만든 뒤
각 note 의 `source_pdf_pages` 를 캐시 텍스트와 대조하면 기계적으로 판정된다.
이 대조를 하기 전까지 A세대 페이지 번호를 신뢰 근거로 쓰지 않는 것이 안전하다.

## 3. 이번 세션 산출물

`_tools/ungok/` — 로컬 전수 실행용 툴체인 (사용법은 `_tools/ungok/README.md`).
`tests/ungok/` — 합성 PDF 기반 회귀 테스트 83개. 원서 없이 전 구간이 돌아간다.

핵심 안전장치(테스트로 고정):

- 근거 없는 인쇄면은 채우지 않는다 (연속 검출 3쌍 미만 구간은 빈칸)
- OCR 교정은 사전 일치 + 편집거리 1 + 독립근거 2개일 때만
- 기존 스키마의 모든 필드가 목적지를 갖거나 근거와 함께 버려진다
- 사람이 쓴 구역은 재생성에서 살아남고 원본은 백업된다
- 누락 note / 중복 / YAML 오류 / broken link 가 있으면 QA 가 exit 1
