## 1. 먼저 알아야 할 사실 (코드 확인 결과)

1. **재진 화면은 한약 전용이 아니다.** `RevisitWorkspace.tsx`는 "문진 없이 개설한 재진"을 통증·한약 구분 없이 하나로 다룬다. 따라서 이 프레임을 구현하면 통증 재진에도 영향이 간다 → 구현 시 프로필 분기가 필요하다(아래 D1·D2).
2. **한약 재진인데 통증 어휘가 나온다.** 오늘 최종 판단 카드는 `PainFinalAssessmentCard`(통증용)를 그대로 쓴다. `시행/예정 처치`(통증 처치 칩)와 `치료 초점`(Task·Load·Capacity 3층 칩)은 한약에 맞지 않는다.
3. 이전 방문이 한약이면 그 값이 통증 모양 필드에 **접혀 들어간다**(`revisitCarryForward.ts`): 최종 변증·병기 → `finalWorkingAssessment`, 치법 → `treatmentFocus`, 처방/계획 메모 → `interventionPerformedOrPlanned`. 저장 형태는 같은 문자열이라 구조는 그대로다.
4. `재진 간단 체크`의 `운동 실제 시행·난이도` 그룹은 한약에는 해당이 없다.
5. 한약에는 **두 번째 재진 경로**가 있다(전체 문진 + 이전 방문). 이번 프레임은 **문진 없는 재진**만 다룬다.

## 3. PO 결정이 필요한 것

- **D1 · 최종 판단 카드를 한약용으로 바꿀까?** 제안: 한약 재진은 `치료 초점`·`시행/예정 처치`를 칩 대신 자유 입력으로(저장 키·EMR 출력은 그대로). 대안: 통증 카드를 그대로 둔다(칩에 `기타`가 있어 입력은 가능). 한약 고유 어휘 칩을 새로 만드는 것은 임상 어휘 결정이라 **제가 정하지 않는다**.
- **D2 · `운동 실제 시행·난이도`를 한약 재진에서 숨길까?** 제안: 숨김. 단, 저장된 값이 이미 있으면 계속 보이게 한다(편집 도중 사라지지 않도록 — CLAUDE.md 표시 조건 규칙).
- **D3 · 재진 안전 확인을 초진처럼 `S` 띠로 올릴까?** 이번 프레임은 올리지 않고 CHECK 카드 안(`새 신경증상·위험신호`·`치료 후 이상반응`)에 둔 채 A에 상태 칩만 표시했다. 한약은 복용 중 이상반응이 핵심이라 띠로 올리는 안도 가능하다.
- **D4 · 임상 루프 상태 바(행 11)** 처리.

## 4. 구현 단계에서 지킬 규칙 (프레임 승인 뒤)

`CLAUDE.md`의 경로 제거·교체 규칙을 그대로 적용한다.
1. **입력 방향**: 행 4~10은 새 칸에서도 같은 저장 키(`finalAssessment`, `carePlan`, `followUpTargets`, `reassessment`, `nextReassessmentPlan`, `revisitQuickCheck`)에 쓰고 EMR·이전 방문 요약까지 도달해야 한다.
2. **출력 방향**: 이전 방문 요약(`painFinalAssessmentSummary`/`herbalFinalAssessmentSummary`)이 읽는 값은 이름도 형식도 바꾸지 않는다.
3. **표시 조건**: D1·D2에서 칸을 숨길 때 값이 있으면 계속 보이고, 지워도 사라지지 않는 래치(`useOpenOnceContent`)를 쓴다.
4. **통증 재진 무변경**: 분기는 프로필 기준으로만 하고, 통증 재진의 출력은 한 글자도 바꾸지 않는다(회귀 테스트 필수).
5. 테스트: 옮긴/숨긴 경로 1개당 소스 텍스트 단언 1개.
