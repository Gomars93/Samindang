## 0. 원장이 알아야 할 것 세 가지

1. **콘텐츠 원본을 찾았다.** PO가 "모름"이라 답한 부위별 원본 문서는 Notion
   「삼인당한의원 › 아카이브(구버전) › 통합 완료(삭제 후보) › 매선 프로토콜」에 있다
   (2025-12-01~06): 경추 패턴 / 어깨 패턴 / 무릎 패턴 / 발목 패턴 / 턱관절, Drive에 고관절
   패턴.md·회전근개.md 사본. 각 페이지는 "정렬 → 움직임 → 패턴(3~4개) → 매선 → 운동 2개"
   형식이다.
2. **그 문서의 출처 주의.** 「매선 프로토콜 목차」에 *"원장님이 만든 발목 프로토콜 포맷
   그대로, 전신으로 확장했습니다"*라고 적혀 있다. 즉 **발목 페이지는 원장 원안 포맷**이고,
   경추·어깨·무릎·고관절 페이지는 그 포맷을 AI가 확장한 초안일 가능성이 있다. 또 같은
   워크스페이스의 정본(「1권 근골격 통증」 집필본, 2026-06)은 경항부를 4패턴이 아니라
   3단계 연쇄(풀린다/헐거워진다/굳고 좁아진다)로 설명한다. **어느 틀을 가설 패턴으로 쓸지는
   원장이 정한다** — 이 문서는 아카이브 페이지의 이름을 옮겨 적었을 뿐이다.
3. **승인 = 코드 3곳 + 빈 칸 0개.** (§4) 빈 칸이 하나라도 남은 팩은 테스트가 승인을 막는다.

## 4. 승인 절차 (부위 1개 = 브랜치 1 = PR 1)

1. 원장이 §3의 8항목을 채운다(문서 또는 이 파일에 직접). 근거 문헌이 있으면 `sourceDocument`에.
2. Sonnet이 팩 파일에 옮겨 적고, 부위별 vignette 테스트를 추가한다(요통
   `tests/lbp-exercise-core20.vignettes.spec.mjs` 형식).
3. `packContentGaps(pack)`이 `[]`인지 확인한다.
4. 코드 3곳을 함께 바꾼다 — 하나만 바꾸면 `npm run test:region-pack`이 실패한다:
   - `regionPacks/<region>.ts`: `productionApproved: true` (조립기 대신 직접 지정)
   - `server/detailCheck.js` `DETAIL_CHECK_REGION_QUESTION_IDS`에 그 부위의 재질문 id
   - `tests/region-pack.spec.mjs` D절 "exactly one approved pack today (lbp)" 단언 갱신
5. Opus 임상 검수 → PO 승인 → merge. 승인 즉시 활성화(PO 결정 2026-09-06 Q4 "즉시").
