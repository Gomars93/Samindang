# 실기기 파일럿 체크리스트 (원장 PC + 태블릿)

이 문서는 사람이 실제 기기(원장 PC, 태블릿, Wi-Fi)를 손으로 조작해야만
확인할 수 있는 부분만 다룬다. 그 외 모든 것(코드 정확성, 테스트, 빌드,
보안 설정, git 위생)은 이미 자동 검증을 통과했다 — 아래 "자동 검증 결과"
절 참고. 개발자가 아니어도 순서대로 따라 하면 된다.

전제: 이 문서의 명령은 프로젝트 루트
`c:\Users\ASUS\Desktop\google drive\samindang-questionnaire`에서 실행한다.
더 자세한 배경/보안 설명은 `docs/RUNBOOK_LOCAL_HANDOFF.md`를 참고.

## 사전 준비 (파일럿 시작 전, 한 번만)

1. 원장 PC에서 프로젝트 빌드:
   ```
   npm run build
   ```
   성공 기준: 마지막 줄에 `✓ built in ...`가 뜨고 `dist/` 폴더가 생긴다.
   에러가 나면 여기서 멈춘다 — 이건 사람이 손댈 부분이 아니라 코드
   문제이므로 개발자에게 알린다.

## 1) 원장 PC에서 서버 시작

`scripts\start-clinic.bat` 파일을 탐색기에서 더블클릭한다.

- **성공 기준**: 새 콘솔 창 2개가 뜬다.
  - 하나는 `samindang-handoff-server` 제목, `samindang handoff server
    listening on http://0.0.0.0:4317` 로그가 보인다.
  - 다른 하나는 `samindang-patient-preview` 제목, `Local:` /
    `Network:` 주소가 뜬다(포트 4173).
- **실패 시**: 창이 바로 닫히거나 에러 문구가 보이면, 사전 준비의
  `npm run build`를 다시 실행했는지 확인한다(`dist\` 폴더가 없으면 경고가
  뜬다). 그래도 안 되면 수동 기동으로 대체한다:
  ```
  npm run server
  ```
  (별도 터미널에서) `npm run preview -- --host`

## 2) Windows 방화벽 / LAN 도달성 확인 (프롬프트가 뜰 경우)

포트 4317(핸드오프 서버)에 처음 접속을 시도할 때 Windows 보안 경고
("Windows Defender 방화벽에서 이 앱의 일부 기능을 차단했습니다")가 뜰 수
있다.

- **뜬 경우**: **개인 네트워크(사설 네트워크)** 체크박스만 선택하고
  **공용 네트워크는 체크하지 않은 채** "액세스 허용"을 클릭한다.
- **안 뜨는데 태블릿이 연결이 안 되는 경우**: 관리자 권한 PowerShell에서
  아래를 한 번 실행한다.
  ```powershell
  New-NetFirewallRule -DisplayName "samindang-handoff-4317" `
    -Direction Inbound -Protocol TCP -LocalPort 4317 `
    -Action Allow -Profile Private
  ```
- **성공 기준**: 원장 PC 자신에서 아래가 응답하면 서버는 정상이다(이 단계는
  방화벽과 무관하게 항상 되어야 한다):
  ```
  curl http://localhost:4317/api/health
  ```
  `{"ok":true,...}`가 보이면 통과.
- **LAN IP 확인** (다음 단계에서 필요):
  ```
  ipconfig | findstr /i "IPv4"
  ```
  `무선 LAN 어댑터` 또는 `이더넷 어댑터` 아래 `192.168.x.x` 형태의 주소를
  적어둔다. **이 값은 코드에 하드코딩하지 않는다** — 매번 이 명령으로 다시
  확인한다(DHCP로 바뀔 수 있음).

## 3) 태블릿에서 설정된 LAN URL 열기

이 단계 전에, 원장 PC 프로젝트 루트에 `.env.local` 파일을 만들고(없으면
새로 만든다) 2)에서 확인한 IP를 넣는다:

```
VITE_SAMINDANG_SERVER_URL=http://<2번에서 확인한 IP>:4317
```

예: `VITE_SAMINDANG_SERVER_URL=http://192.168.0.10:4317`

파일을 저장한 뒤 **다시 빌드**해야 반영된다:
```
npm run build
```
그리고 1)의 `start-clinic.bat`을 다시 실행(또는 두 콘솔 창을 닫았다가
재실행)한다.

- 태블릿 브라우저에서:
  ```
  http://<2번에서 확인한 IP>:4173
  ```
- **성공 기준**: 문진 시작 화면이 뜬다(원장 PC와 같은 화면).
- **실패 시**:
  1. 태블릿과 원장 PC가 **같은 Wi-Fi**에 있는지 확인(게스트 Wi-Fi는 기기간
     통신을 막을 수 있음 — AP 격리 확인).
  2. IP가 바뀌지 않았는지 2)의 `ipconfig` 명령으로 재확인.
  3. 2)의 방화벽 규칙이 적용됐는지 재확인.

## 4) 테스트 문진 1건 제출

태블릿에서 실제 환자인 것처럼 문진을 끝까지 진행한다. 이름/전화번호 등은
**테스트임을 알아볼 수 있는 값**을 쓴다(예: 이름 "테스트환자", 전화번호
뒷자리 `0000`) — 5)에서 완료 후 반드시 삭제할 것이므로 실제 개인정보를
쓰지 않는다.

- **성공 기준**: 문진 마지막에 "문진이 접수되었습니다" 류의 완료 화면이
  뜨고, 오류 배너가 없다.
- **실패 시("전송에 실패했습니다" 류의 오류 화면이 뜨면)**:
  - 화면에 재시도 버튼("다시 시도")이 있으니 눌러본다.
  - 그래도 안 되면 3)의 URL이 정확한지, 서버 콘솔 창이 아직 떠 있는지
    확인한다.
  - 문진 내용 자체는 사라지지 않는다 — 서버가 안 되더라도 문진은 끝까지
    진행/완료되며, 개발자용 화면에 남은 내용을 수기로 옮길 수 있다(이건
    임시 우회 수단이지 정상 경로가 아니다).

## 5) 원장 PC 화면에 올바르게 나타나는지 확인

원장 PC(서버가 떠 있는 그 PC)의 브라우저에서:
```
http://localhost:4173/#doctor
```

- 목록 헤더의 데이터 소스가 "서버 제출목록"으로 되어 있는지 확인한다(아니면
  화면에서 전환).
- **성공 기준**:
  - 방금 제출한 테스트 문진이 목록에 나타난다(빨간 "신규 1" 배지).
  - 항목을 클릭해서 열면 방금 입력한 테스트 이름/증상 등이 그대로
    보인다 — 다른 제출과 섞이지 않았는지 확인(오늘 처음이면 비교 대상이
    없을 수 있음).
  - **출생 시간대**(자시~해시 중 환자가 고른 값)가 그대로 보인다.
    명리 계산 섹션(일주·월주·연주 등)이 "정책 승인 대기"로 표시되는 것은 **정상이며 확인 대상이 아니다**
    — 2026-09-20 PO 결정으로 파생 계산은 임상에 쓰지 않는다
    (`docs/MYUNGRI_CALCULATION_POLICY_PENDING.md` 같은 날 항목).
- **실패 시**:
  - "불러오는 중…"이 계속 떠 있으면 최대 5초(폴링 주기) 기다린다.
  - "서버에 연결할 수 없습니다"가 뜨면 **다시 시도** 버튼을 누르고, 그래도
    안 되면 서버 콘솔 창이 살아있는지, `curl
    http://localhost:4317/api/health`가 응답하는지 확인한다.

## 5-b) 목(NECK) 환자 — 운동 팩이 보이는지 확인 (2026-09-07 목 팩 활성화 이후)

4)에서 테스트 문진을 **목통증 주호소**로 한 번 더 제출하고, 5)와 같은 원장 화면에서 연다.

- **성공 기준**:
  - 안전 패널 아래에 목 가설 칩(축성 가동성 제한 / 신경근 관여 / 경추성 두통 / 움직임 조절 / 어깨·말초)이 보인다.
  - 검사 카드에 `C5–T1 신경학적 기준선`과 `UMN 징후`가 있다. 기록 전에도 후보 카드는 보이되 `팔 신경 가동성
    슬라이더` 한 항목만 "신경 상태 미기록" 이유로 보류된다; 둘 다 NEGATIVE로 기록하면 그 항목도 후보에 든다;
    하나라도 POSITIVE로 기록하면 후보 전체가 잠긴다(안전 재평가 우선) — 셋 다 정상 동작이다.
  - 후보 카드에 채택 / 보류 / 배제 버튼이 있다.
  - 어깨 우세(NS01)로 제출한 테스트 문진은 목 팩이 **보이지 않는다** — 안전 패널만 보이면 정상이다.
- **실패 시**: 목 칩·검사 카드가 전혀 없으면 `npm run test:region-pack`과 `npm run test:neck-exercise-vignettes`를 돌려
  본다(둘 다 통과하면 빌드가 옛 것이다 — 사전 준비의 `npm run build`를 다시).
- 파일럿 관찰 기록 절차는 `docs/NECK_PILOT_OBSERVATION_LOG_v1.0.md` §1.
- **어깨·무릎·발목/발·손목/손도 승인됨(2026-09-07)**: 각 주호소로 테스트 문진을 1건씩 제출해 가설 칩·검사 카드·후보 카드가
  보이는지 같은 방식으로 확인한다. 어깨는 NS01 "어깨 우세"로 답해야 어깨 팩이 뜬다(목 우세·비슷함은 목 팩). 고관절·팔꿈치·턱관절은
  아직 DRAFT라 안전 패널만 보이면 정상이다.

## 5-c) 한약 환자 — 문진부터 EMR 복사까지 통과 (2026-09-20 신설)

통증 경로(5-b)는 6부위 전부 절차가 있는데 **한약 경로만 없었다.** 한약 환자를 받기 전에
이 절을 한 번 끝까지 통과한다. 두 갈래를 각각 1건씩 제출한다.

### (가) 기력·체력 / 몸 상태 점검 목적 — 20화면

첫 화면(방문 목적)에서 **"한약·보약 상담"** → 다음 화면("한약 상담의 주된 목적은 무엇인가요?")
에서 **"기력·체력 회복"**.

> "전반적인 몸 상태 점검" / "상담 후 결정"을 골라도 **같은 경로 20화면**이다 — `'불편한 증상 치료'`만
> 다른 갈래로 간다((나)). 셋 중 아무거나 골라도 이 절의 성공 기준은 동일하다.

- **거치는 구간**: 상담 내용 2 → 전신 정보 8 → 병력 6 → 출생 정보 3 → 마무리 1
- **성공 기준(환자 태블릿)**:
  - 전신 정보 8문항이 전부 나온다 — `CONST_*` 4개(기력/수면/소화/대변)와
    `HERB_*` 4개(**식욕 / 한열 / 갈증 / 땀**). 하나라도 건너뛰면 라우팅이 깨진 것이다.
  - 출생 정보에서 **시간대 12지지 목록**(자시~해시 + "잘 모르겠어요")이 보인다.
  - 통증 문항(`PAIN_*`)은 **하나도 나오지 않는다**.

### (나) 증상 치료 목적 — 25화면

같은 첫 화면에서 **"한약·보약 상담"** → **"불편한 증상 치료"** → 주 증상(예: 속·소화).

- **성공 기준**: (가)의 8문항에 더해 방문 목적 2 + 그 증상의 상세 모듈 3화면이 앞에 붙는다.

### (다) 원장 화면 — 두 건 모두

`http://localhost:4173/#doctor` 에서 방금 제출한 건을 연다.

- **성공 기준**:
  - 화면 상단 프로필 배지가 **`한약·전신`** 이다(`통증`이나 `혼합`이 아니다).
  - **한약 판단 3칸**(최종 변증·병기 / 치법 / 처방·계획 메모)과 **추적할 증상** 칸이 보인다.
  - 설진·맥진·복진 관찰 체크리스트가 보인다.
  - 전신 정보 8문항의 답이 그대로 읽힌다.
- **실패 시**: 배지가 `통증`으로 뜨면 문진에서 방문 목적을 잘못 골랐거나 빌드가 옛 것이다
  (`npm run build` 재실행).

### (라) EMR 복사 — 이 절의 진짜 목적

원장 화면에서 **판단 3칸을 실제로 타이핑해 채운 뒤** EMR 복사를 누르고,
메모장에 붙여넣는다.

- **성공 기준**: 붙여넣은 텍스트에 `최종 변증·병기:` / `치법:` / `처방/계획 메모:` /
  `추적할 증상:` 줄이 있고, **방금 타이핑한 내용이 그 줄에 들어 있다.**
- **왜 이걸 반드시 확인하나**: 과거에 정확히 이 지점에서 두 번 사고가 났다 —
  한약 레코드가 빈 EMR을 복사하고 "복사됨"을 띄운 적(D-1), 원장이 타이핑한 3필드가
  출력에서 사라진 적(D-2). 지금은 고쳐져 있고 테스트도 있지만, **실기기에서 눈으로
  확인한 적은 이 절차가 처음이다.**

### 알려진 사항 (진료에 지장 없음, 놀라지 말 것)

- 한약 화면의 `다음 방문 확인` 항목이 두 군데에 나온다(백로그 O-6).
- 관찰 항목을 재평가로 승격하면 상태가 `UNCLEAR`로 찍힌다(백로그, `DoctorWorkspace.tsx:420`).
- 명리 계산 섹션의 "정책 승인 대기" 표시 — 위 5)의 설명대로 무시한다.

## 5-d) 갱년기 환자 — 문진부터 원장 화면, SOP 중단, 소요시간까지 (2026-10-02 신설)

통증(5-b)·한약(5-c)과 별개로 **갱년기 경로는 실기기에서 한 번도 돌려 본 적이 없다.** 첫 갱년기 환자를 받기 전에
이 절을 직원과 함께 한 번 끝까지 통과한다. 가짜 환자 **2명**을 제출한다. 시작 전에 `git pull`(또는
`scripts\setup-and-start-clinic.bat`)로 최신 main인지 확인한다.

### (가) 정상 흐름 1명 — 소요시간 재기

첫 화면에서 성별 **여성** → 방문 목적 **여성 건강** → **"갱년기·중년기 건강"**을 고르고 끝까지 진행한다.
직원이 **시계로 처음 화면부터 "접수되었습니다"까지** 시간을 잰다(아래 (마)의 자동 집계와 대조용).

- **성공 기준(환자 태블릿)**:
  - 갱년기 문항 위에 **단계 탭 5개**(1 생애단계 … 5 목표)가 보이고 현재 단계만 채워져 있다.
  - **첫 갱년기 화면**("최근 1년, 월경(생리)은 어땠나요?")에서 선택지 **5개가 스크롤 없이 한 화면에** 다 보인다.
    (1024×768 계산값으로 여유가 28px뿐이다 — 실제 태블릿에서 5번째 "수술·약 때문에 알기 어려움"이 잘리면
    **그 기기 이름과 화면 크기를 적어 개발자에게 알린다.** 이 선택지는 안전 선택지라 숨으면 안 된다.)
  - "입력이 어려워요"(직원 호출) 버튼이 모든 갱년기 화면에 있다.
- **적어 둘 것**: 총 소요 시간, 가장 오래 멈춘 화면, 환자가 헷갈려 한 문항.

### (나) 원장 화면 — (가)에서 제출한 건

`http://localhost:4173/#doctor` 에서 데이터 소스를 **"서버 제출목록"**으로 바꾸고 방금 건을 연다.

- **성공 기준**:
  - 목록에 **"갱년기·중년기 건강"**으로 보이고 안전 배지가 **해당 없음(CLEAR)**이다.
  - 레인2 맨 위에 **"갱년기 진료 요약"** 8카드(스냅샷 · LIFE STAGE · TOP SYMPTOMS · BASELINE PRO · DIAGNOSTIC HYPOTHESIS · REFUTATION TRIGGER · REFERRAL / UNRESOLVED · CARE PLAN)가 보인다.
  - BASELINE PRO는 **주증상 / 수면 만족도 / 일상 기능 방해 3행**이다.
  - 원장이 **생애단계 선택, 4주 목표 1개 선택**을 해 보고 화면을 닫았다 열어도 그대로 남는다(저장 확인).
- **실패 시**: 목록에 아무것도 없으면 데이터 소스가 "예시 데이터"인 것이다.

### (다) SOP 중단 리허설 1명 — 가장 중요

두 번째 가짜 환자로 같은 경로를 가다가 안전 확인 화면(**"지금 이런 상태가 있나요?"**)에서
**"자해·자살에 대한 구체적인 생각이나 계획이 있어요"**를 고른다.

- **성공 기준(환자 태블릿)**: 문진이 **그 자리에서 멈추고** "직원이 바로 도와드릴게요"만 보인다.
  계속·뒤로 버튼이 없고, 진단·이유·전화번호 문구가 **없다.**
- **성공 기준(원장 화면)**: 목록에 **URGENT**, 원장 화면에 **"MID_08에서 중단됨"** 표시와 **SOP 4줄**이 보인다.
  뒤 문항(병력·복약·임신 여부)이 비어 있다는 안내도 보인다.
- **직원 동선 연습(이 리허설의 진짜 목적)**: 태블릿이 멈춘 순간 직원이 **누구를 부르고, 환자 곁에 누가 남고,
  원장이 몇 초 만에 오는지** 시계로 재서 적어 둔다. SOP 4줄(혼자 두지 않기 → 직접 묻기 → 112·119/109 → 기록)을
  원장이 소리 내어 한 번 읽어 본다.
- **끝낼 때**: 직원이 완료 화면 **오른쪽 아래 구석을 2초 이상** 눌러 초기화한다(아래 "직원 리셋 제스처").

### (라) 안전 선택지가 쉽게 눌리는지

안전 확인 화면(MID_08·09)의 선택지는 여백을 줄였지만(최소 높이 72px 유지) **손가락 크기가 다양하므로**
직원 2명 이상이 직접 눌러 보고, 의도하지 않은 선택지가 눌리면 그 기기와 함께 알린다.

### (마) 정리 — 자동 집계로 숫자 확인

리허설이 끝나면 원장 PC에서:

```
npm run pilot:midlife-observation
```

- **성공 기준**: 갱년기 제출 2건, 안전 분포에 **URGENT 1 + 해당 없음 1**, **SOP 중단 1건**이 나오고
  (가)에서 시계로 잰 시간과 **자동 집계 시간이 대략 맞는다.** 많이 어긋나면 알린다.
- 출력에 이름·전화번호·자유서술이 **없는지** 눈으로 확인한다.
- 그다음 아래 "테스트 제출 정리"로 가짜 제출을 **반드시 지운다**(안 지우면 실제 파일럿 숫자가 오염된다).

### 알려진 사항 (진료에 지장 없음)

- 갱년기 문진에서 "약 3분" 안내는 일부러 넣지 않았다 — 위 (가)의 실측 시간이 나온 뒤 결정한다.
- 원장 패널은 1440×900 한 화면보다 길어 **스크롤이 필요하다**(기능 문제 아님).
- SOP 중단 환자는 병력·복약·임신 여부가 비어 있으므로 **한약 처방 전에 구두로 확인**한다.

## 5-e) 요통(허리) 환자 — 정상 / 긴급 신호 / 외상, 세 가지를 직원과 한 번씩 (2026-10-02 신설)

요통은 가장 많이 올 주호소인데도 5)~5-d)는 요통만 따로 확인하지 않는다. 가짜 환자 **3명**을 제출한다.
**전부 첫 화면에서 "아픈 곳 치료" → "허리·골반"**으로 들어간다. 시작 전에 `git pull`(또는
`scripts\setup-and-start-clinic.bat`)로 최신 main인지 확인한다. 갱년기와 달리 요통의 긴급 신호는
**문진을 멈추지 않는다** — 직원 확인 화면에서 직원이 "계속하기"를 눌러야 이어진다(아래 (나)).

### (가) 정상 흐름 1명 — 소요시간 재기

"허리 통증이나 불편감이 가장 멀리 어디까지 내려가나요?"에서 **"허리만"**, 다리 질문에서 **"없어요"**, 안전 질문 둘은 **"해당 없음"**,
외상은 **"아니요"**로 끝까지 진행한다. 직원이 **시계로 처음 화면부터 "접수되었습니다"까지** 잰다.

- **성공 기준(환자 태블릿)**:
  - "허리와 별개로 다리가 저리거나 둔하거나 힘이 빠지나요?"에서 **"없어요"**를 고르면 다리 느낌·다리 쪽 두 화면이
    **나타나지 않고 건너뛴다.**
  - "입력이 어려워요"(직원 호출) 버튼이 요통 화면에 있다.
  - 완료 화면이 뜨고 오류 배너가 없다.
- **성공 기준(원장 화면, (라)에서 함께 확인)**: 안전 확인 칩 **"안전"**, 추가 권장 검사에 **"목표 기능 재현 검사"**·**"요추 능동 움직임 반응 검사"**.
- **적어 둘 것**: 총 소요 시간, 가장 오래 멈춘 화면, 환자가 헷갈려 한 문항.

### (나) 긴급 신호 1명 — 직원 확인 화면과 직원 동선

두 번째 가짜 환자는 "허리와 별개로 다리가…"에서 **"있어요"**, 다리 느낌 **"저리거나 찌릿함"**, 쪽 **"오른쪽"**을 고른 뒤
"허리·다리와 함께 최근 새로 생긴 변화가 있나요?" 화면에서 **"소변이 잘 나오지 않거나 시작하기 어려워짐"**을 고르고 제출한다.

- **성공 기준(환자 태블릿)**: 제출하자마자 **"먼저 확인이 필요한 내용이 있습니다. 태블릿을 직원에게 보여주세요."**가 뜬다.
  진단명·병명 문구는 **없다.** 직원이 **"확인했어요, 계속하기"**를 누르면 나머지 문진이 이어진다(갱년기 중단과 다른 점).
- **직원 동선 연습(이 리허설의 진짜 목적)**: 화면이 뜬 순간부터 **직원이 원장을 부르고, 원장이 환자를 직접 확인하기까지**
  몇 초 걸리는지 시계로 적어 둔다. 직원이 원장 확인 **전에** "계속하기"를 누르지 않기로 정한다(누르면 환자가 문진을 이어 간다).
- **성공 기준(원장 화면)**: 이 건의 안전 확인 칩이 **"긴급 확인 필요"**로 보인다. "안전 확인 전까지 일상적인 운동/치료 추천은 잠깁니다" 안내도 보인다.
- 끝낼 때 직원이 완료 화면 **오른쪽 아래 구석을 2초 이상** 눌러 초기화한다(아래 "직원 리셋 제스처").

### (다) 외상 1명 — 인터럽트 없이 "확인 필요"만 남는지

세 번째 가짜 환자는 안전 질문 둘은 **"해당 없음"**, "최근 넘어짐·부딪힘 등 허리에 큰 충격이 있었나요?"에서 **"네"**로 진행한다.

- **성공 기준(환자 태블릿)**: 직원 확인 화면이 **뜨지 않고** 그대로 끝까지 진행된다(비응급 신호는 환자를 놀라게 하지 않는다).
- **성공 기준(원장 화면)**: 이 건의 안전 확인 칩이 **"확인 필요"**다("긴급 확인 필요"가 아니다).

### (라) 원장 화면 — 세 건 모두

`http://localhost:4173/#doctor`에서 데이터 소스를 **"서버 제출목록"**으로 바꾸고 세 건을 차례로 연다.

- **성공 기준**: 각 건에 **"안전 확인 — 허리(LBP)"** 패널이 있고, 위 (가)(나)(다)에서 적은 칩이 그대로 보인다.
  **"치료 안전"**, **"신경근성 증상 가능성"** 칩도 있다((나)는 다리 증상이 있어 "있음").
  (나)에는 다리 증상이 있으므로 **"하지 근절(myotome) 근력 검사"**·**"감각 검사"**·**"반사 검사"**가 추가 권장 검사에 보인다.
- **실패 시**: 패널이 없으면 데이터 소스가 "예시 데이터"인 것이다. 패널은 있는데 칩이 틀리면 **어느 건의 어느 칩인지**
  화면을 찍어 알린다.

### (마) 긴급 신호 선택지가 쉽게 눌리는지

(나)의 변화 화면은 선택지가 길다(6개). 직원 2명 이상이 직접 눌러 보고 **글이 잘리거나 의도하지 않은 선택지가 눌리면**
그 기기와 함께 알린다. 화면이 길어 스크롤이 필요하더라도 **"해당 없음"과 "잘 모르겠어요"가 눌러지는지**만 확인한다.

### 정리

리허설이 끝나면 아래 "테스트 제출 정리"로 가짜 제출 **3건을 반드시 지운다**(안 지우면 실제 파일럿 숫자가 오염된다).

### 알려진 사항 (진료에 지장 없음)

- 요통은 갱년기와 달리 **소요시간·긴급 신호 건수를 세는 자동 집계가 없다**(`pilot:midlife-observation`은 갱년기 전용, `pilot:lbp-stage`는 운동 단계 분포만 센다). 소요시간은 직원 시계로만 잰다.
- 환자가 직원 확인 화면 뒤에 문진을 이어 가므로, **응급이면 원장이 직접 확인할 때까지 환자를 혼자 두지 않는다**는 원칙은 직원 교육으로 지킨다 —
  태블릿이 막아 주지 않는다.
- 이 점검은 요통 경로만 본다. 목·어깨는 5-b), 한약은 5-c), 갱년기는 5-d)를 따른다.

## 5-f) 진료실1 서버 + 진료실1·진료실2 원장 화면 + 부팅 후 자동 시작 (2026-10-02 신설)

서버는 **항시 켜 두는 진료실1 PC**에서 돌고, 원장 화면은 **진료실1·진료실2 Windows Chrome**에서 본다(환자 태블릿은 같은 서버에 문진을 제출만 한다).
이 절의 어느 것도 실기기에서 한 번도 돌려 본 적이 없다 — 첫 환자 전에 (가)~(마)를 순서대로 한다.

### (가) 먼저 확인 — 환자 데이터가 구글 드라이브로 나가지 않는지

저장소 폴더가 구글 드라이브(`...\google drive\...`) 아래에 있으면, **자동 시작 스크립트는 데이터 폴더를 따로 지정하지 않는다**
(`scripts\start-doctor-api.bat`은 환경변수에서만 읽는다). 값이 없으면 서버는 저장소 안 `.data\submissions`에 환자 문진을 쓰고,
그 폴더가 클라우드로 동기화될 수 있다. 아래 (나)의 `SAMINDANG_DATA_DIR`을 **반드시** 먼저 설정한다.

### (나) 진료실1 PC에서 한 번만 — 사용자 환경변수 3개

PowerShell(관리자 권한 불필요)에서 한 줄씩 실행한다. `<서버 IP>`는 진료실1 PC의 LAN IP(`ipconfig | findstr /i "IPv4"`)다.

```powershell
[Environment]::SetEnvironmentVariable('SAMINDANG_DATA_DIR', 'C:\samindang-data\submissions', 'User')
$b = New-Object byte[] 24; [Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b)
$token = ($b | ForEach-Object { $_.ToString('x2') }) -join ''
[Environment]::SetEnvironmentVariable('SAMINDANG_DOCTOR_TOKEN', $token, 'User')
[Environment]::SetEnvironmentVariable('SAMINDANG_ALLOWED_ORIGINS', 'http://<서버 IP>:4173', 'User')
$token
```

- 마지막 줄이 **닥터 토큰**(48자)이다. **종이나 비밀번호 관리자에 적어 두고, 채팅·문서·git·사진에 남기지 않는다.** 이 값은 자동으로 바뀌지 않는다.
- 환경변수는 **새로 연 프로그램부터** 적용된다. 설정 후 진료실1 PC를 한 번 재부팅하거나 서버를 다시 시작한다.
- 허용 주소는 브라우저가 페이지를 연 주소(`:4173`)다. 서버 주소(`:4317`)가 아니다.

### (다) 워크스테이션 이름 — 진료실 두 곳

워크스테이션 이름은 영문·숫자·`-`·`_`만 된다(한글 "진료실1" 불가). 진료실1 = `ROOM-1`, 진료실2 = `ROOM-2`로 쓴다.
저장소 폴더의 `.env.local`에 아래 줄을 **추가**하고(기존 `VITE_SAMINDANG_SERVER_URL` 줄은 그대로) 다시 빌드한다:

```
VITE_SAMINDANG_WORKSTATIONS=ROOM-1,ROOM-2
```
```
npm run build
```

### (라) 진료실1 PC의 주소를 고정한다

공유기 설정에서 진료실1 PC에 **고정 IP(DHCP 예약)**를 준다. IP가 바뀌면 태블릿 주소, `.env.local`, (나)의 허용 주소가 모두 틀어진다.
IP를 정하면 `.env.local`의 `VITE_SAMINDANG_SERVER_URL=http://<서버 IP>:4317`도 같은 값인지 확인하고 `npm run build`를 다시 한다.

### (마) 부팅 후 자동 시작

```
powershell -ExecutionPolicy Bypass -File scripts\register-clinic-autostart.ps1
```

- 이 등록은 **로그온 시** 서버 2개(4317, 4173)를 띄운다(부팅만으로는 안 뜬다). 진료실1 PC를 **재부팅한 뒤 한 번 로그인**해야 하고,
  로그인 뒤에는 화면을 잠가도(Win+L) 서버는 계속 돈다. 정전·업데이트 재부팅 뒤에는 **누군가 로그인해야 한다** — 이 점을 직원에게 알린다.
- 전원 옵션에서 **절전·최대 절전을 끈다**(꺼지면 두 진료실이 동시에 멈춘다).
- 확인: `Get-ScheduledTask -TaskName SamindangDoctorAPI, SamindangPatientPreview | Get-ScheduledTaskInfo` 와 `curl http://localhost:4317/api/health`.
- 서버 시작 로그에 `doctor token: set`이 보이면 (나)가 적용된 것이다. `not set`이면 환경변수가 아직 안 읽힌 것이다.

### (바) 원장 화면 접속 — 진료실1 · 진료실2

두 PC 모두 Chrome에서 같은 주소로 연다:

```
http://<서버 IP>:4173/#doctor
```

- 처음 열면 **"원장 인증 필요"**(토큰 입력)와 **"워크스테이션 설정 필요"**(진료실1 = `ROOM-1`, 진료실2 = `ROOM-2` 선택) 배너가 나온다. 토큰은 탭을 닫으면 사라지므로 **매일 아침 다시 입력**한다.
- **진료실1 PC에서도 토큰이 필요할 수 있다.** 앱은 서버 주소를 LAN IP로 빌드해 두고, 서버는 자기 LAN IP로 들어온 요청을
  "같은 PC"(loopback)로 보지 않는다(이 세션의 Linux에서 재현: 127.0.0.1은 허용, 자기 LAN IP는 토큰 없이 403). Windows에서 같은지는 **여기서 직접 확인한다.**
- 데이터 소스는 **"서버 제출목록"**이어야 한다.
- **성공 기준**:
  - 진료실1·진료실2 둘 다 같은 제출 목록이 보인다.
  - 진료실1에서 한 환자를 "진료 중"으로 열어도 진료실2의 "진료 중" 표시는 **그대로**다(반대도 같다).
  - 가짜 문진 1건을 태블릿에서 제출하면 두 PC 모두 5초 안에 목록에 나타난다.
  - 토큰을 넣지 않은 다른 PC(예: 태블릿 브라우저에서 `#doctor`)는 목록이 **안 보인다**(403 또는 연결 실패).
- **실패 시**: 목록이 안 뜨면 (나)의 허용 주소가 `http://<서버 IP>:4173`와 **한 글자도 다르지 않은지**, 방화벽에서 4173·4317이 열렸는지(2절), 두 PC가 같은 공유기에 있는지 본다.

### (사) 수동 스모크 테스트 7항목

`docs/MULTI_WORKSTATION_CONTRACT.md`의 "LAN Doctor 접근 수동 스모크 테스트" 7항목을 진료실2 PC → 진료실1 서버로 한 번 체크한다.

### 알려진 사항 (진료에 지장 없음)

- 토큰은 평문 헤더로 LAN을 오가고 TLS·로그인 기록이 없다. **환자용 Wi-Fi와 같은 네트워크에서는 쓰지 않는다** — 원내 전용망(또는 환자용 게스트 Wi-Fi 분리)이 전제다.
- 진료실1 PC가 꺼지면 두 진료실과 태블릿 제출이 모두 멈춘다. 환자 문진은 이때 태블릿에서 "전송 실패"로 보인다.
- 이 점검은 접속 구성만 본다. 문진·원장 화면 내용은 5-d)(갱년기)·5-e)(요통) 등 주호소별 절을 따른다.

4. **audit.log 자체는 날짜 기준 자동 보존기한이 없다**(제출 데이터는 30일

   의도적으로 미룬 부분이라고 명시하고 있어 리스크가 작다.
5. **`npm run preview -- --host`의 `--host` 플래그 중복.** 동작에 영향
