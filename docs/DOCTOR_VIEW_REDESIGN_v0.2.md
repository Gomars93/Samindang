## 1. 현재 UI의 가장 큰 문제 10개 (Opus 검수 반영판)

1. **위험 상태가 시각적으로 인코딩되어 있지 않다.** 안전 패널 10종
   (`.doctor__lbpSafety*`)에는 **CSS가 한 줄도 없다**. `--urgent_review` modifier는
   아무 효과가 없고, `안전/확인 필요/긴급 확인 필요`가 픽셀 단위로 동일하게 보인다.
   유일한 차이는 칩 속 한글 3~7글자다. (v0.1은 이를 "반복 패턴"으로 오진 — 진짜 문제는
   반복이 아니라 인코딩 부재다.)
2. **URGENT의 단일 출처가 없다.** `requires_staff_check`(배너·목록 ⚠)는 general/GI/
   Bowel만 포함하고 모듈별 URGENT_REVIEW를 반영하지 않는다. 무릎 패혈성 관절염
   (KNEE_07) 양성 환자가 목록에서 ⚠ 없이 평범한 행으로 보인다.
3. **행동이 가장 멀리 있다.** 판단 입력·진찰 소견·EMR 복사가 화면 맨 아래 — 20개 섹션을
   스크롤해야 "기록"에 닿는다.
4. **저장 실패가 조용히 사라진다.** `onSave`는 await되지 않고, 실패 시 아무 표시가
   없으며, 성공해도 "아직 저장되지 않음" 문구가 뜬다(`JudgmentPanel.tsx:273`).
5. **EMR 편집이 소리 없이 파괴된다.** 새 recording_id 도착 시 편집 중 텍스트를 5초
   폴링이 무조건 덮어쓴다(코드 주석에 "의도된 동작"으로 명시되어 있으나 진료 중 작업물
   소실이다).
6. **모든 섹션이 같은 시각 무게 + 항상 빈 legacy 섹션 3개 상주.** "동반문제"는 새
   문진에서 구조적으로 항상 비어 있는데 매번 3줄을 차지한다.
7. **불리언 칩 31개 중 다수가 `아니요`.** HIP 환자 한 명이 칩 7개를 보는데 5~6개가
   음성이다. "빈 값은 줄을 만들지 않는다" 원칙이 계산 플래그에는 적용된 적이 없다.
8. **타이포 위계가 실질 붕괴 상태.** 스케일이 12~15px에 압축되어 있고, 선언된
   Pretendard는 로드되지 않아(`@font-face`/번들 없음) 실제로는 Malgun Gothic
   400/700 2종으로 렌더될 가능성이 높다.
9. **desktop/tablet 레이아웃 부재.** 1080px 단일 컬럼, 핵심 진료 영역 3~4 viewport.
10. **워크플로의 절반이 미완성.** `in_consultation`/`completed` 상태는 라벨·서버
    계약까지 있으나 이를 세팅하는 UI가 없다(코드가 세팅하는 건 `viewed` 하나) —
    목록이 영구히 쌓인다.

## 2. 유지해야 할 좋은 점

- **Provenance 3분류** (환자 보고 / 시스템 계산 / 원장 입력) — 코드·문구 레벨에서 이미
  엄격. 재설계는 이를 시각 언어로 승격만 한다.
- **"빈 값은 줄을 만들지 않는다"** (Field) + **"안 물어봄 ≠ none/unknown 응답"** muted
  구분 — 그대로 계승하고, §11.6에서 계산 플래그에도 같은 급의 규칙을 신설한다.
- **안전 우선 순서 불변식** — 새 IA에서도 보존 (§8.4의 새 검증 방식으로).
- **fail-closed 잠금 문구** — 의미 축약 금지, 접힘과 무관하게 상시 노출로 강화.
- **위험신호 중복 회피** (배너가 전체를 보이면 다른 곳은 포인터만).
- **EMR 수동 재조립 escape hatch** (`요약 다시 만들기`) — 덮어쓰기 금지 규칙(§11.5)의
  구현 기반으로 재사용.
- **참고 증상은 진단처럼 보이면 안 된다** (§19/§23) — muted 유지.
- **명리 "계산 완료 ≠ 임상 해석 완료" 방어 문구** — compact 카드에서도 소실 금지 (§4).

## 4. 새 정보 구조 (4-Level Hierarchy)

**Level 1 — 즉시 (진입 후 3~5초):** 환자 헤더 밴드
- `환자명 · 휴대폰 끝4자리 · 성별/나이` (나이는 파생 — `계산` 태그. **차트번호는
  Sigma 연동 필드가 payload에 생기기 전까지 표시하지 않는다** — Opus M6)
- 주호소(최대 타이포) + 기간·빈도 한 줄
- **안전 종합 pill** — §11.1의 `deriveSafetyOverview` 단일 출처. 3상태:
  `긴급 확인`(red) / `확인 필요`(amber) / `안전 확인됨`(mint)
- **응답 모순 배지** — `flags.response_consistency_review`가 true면 헤더에 독립 amber
  배지 `응답 모순 — 확인 필요` (의뢰서 목표 ③, Opus N4)
- 직전 방문 슬롯: **이력 데이터 모델 도입 전까지 렌더하지 않는다. 플레이스홀더도
  금지** (§13 invariant 8)

**Level 2 — 오늘 판단의 근거 (좌측 컬럼):**
1. **통합 안전 확인** (§11.3) — 부위 행 + 일반 안전정보(비-부위 6종) + 응답 모순 행
2. **문진 핵심** — 유의미 응답 우선, 원시 전체는 펼치기
3. **추가 상세상담** — `routing.additional_module` 존재 시 문진 핵심 바로 아래 동일
   규칙의 명시적 블록 (FULL 2차 모듈 — Opus N3). 이 모듈의 안전 플래그는 이미 1의
   통합 리스트에 행으로 존재한다(§11.2 게이트가 primary/additional을 구분하지 않으므로)
4. 약물·병력·알레르기·수술 / 임신·수유 파생

**Level 3 — 오늘 입력 (우측 레일):**
- 오늘 확인 목록 (§11.4) · 진찰 소견 radio (LBP/Shoulder) · 판단 기록 compact 폼 ·
  저장 상태 인디케이터 (§11.7) · **EMR 시트 열기 버튼 + 진료 완료 버튼** (§11.5, §11.8)

**Level 4 — 참고 (1클릭 접근):**
- 명리 compact(+"오행 분포/한열조습: 해석 규칙 미확정 · 원장 판단 영역" 문구 **보존**,
  Opus N11) ▸ 3열 감사 뷰 펼치기 · 전신·한약 참고 · 참고 증상·기타 · 원시 응답 전체 ·
  transcript 원문 · 원본 JSON(⚙)

## 5~6. 레이아웃 후보와 판정 (v0.1 §5~6 유지, 수정 1건)

3안(A: Summary+Action Rail / B: Timeline / C: Progressive Cockpit) 비교와 B·C 탈락
논거는 v0.1과 동일. **수정:** v0.1이 A의 장점으로 꼽은 "양 컬럼 독립 스크롤"은 폐기
한다 — 이 저장소의 sticky-vs-overflow 이력(`styles.css:49~66` 병목 10)과 뷰포트보다 긴
sticky의 불성립(Opus P1) 때문이다. A의 진짜 장점은 스크롤 방식이 아니라 **읽기/쓰기
공간 분리** 그 자체다.

## 7. 최종 추천안 — Option A + 뷰포트 예산 우선 설계

- **단일 페이지 스크롤 컨텍스트** (컬럼별 `overflow` 금지, `html.doctor-mode` 무변경).
- 우측 레일은 **콘텐츠를 뷰포트 예산 안으로 먼저 설계**한 뒤에만 sticky를 쓴다:
  1440×900 기준 레일 콘텐츠 ≤ 560px (예산표 §8.1). 예산 초과 상황(에러 다발 등)에서는
  sticky가 자연히 풀리며 페이지와 함께 스크롤 — graceful degradation.
- **EMR은 레일 상주 블록이 아니라 시트(sheet)로 분리** (§11.5) — 레일에는 상태 칩 +
  열기 버튼만. 근거: EMR 정리는 진료 종료 시점의 배타적 작업이지 근거를 보며 병행하는
  작업이 아니며, recorder 결과가 없는 방문(초진 대부분)에서 빈 블록을 만들지 않는다.
- Level 2 상세(원시 응답 전체·명리 감사 뷰)는 progressive disclosure — 단 **접힘
  정책은 안전 상태별로 §11.3이 규정한다** (요약-즉시/원문-1클릭 원칙은 CLEAR에만 적용).

```
└───────────────────────────────────────────────────────────────────────────┘
```
- 안전 배지는 **행 단위로 `deriveSafetyOverview`를 사용** — 서버 목록 API가 모듈 안전
  상태를 내려주지 않는 현재는 `requires_staff_check`만으로 URGENT를 판정할 수밖에
  없으므로, **P2에서 서버 목록 응답에 overview 필드 추가를 함께 계상한다**
  (`server/store.js` — 저장된 submission으로부터 파생, 새 임상 계산 아님).
- 4상태(신규/확인함/진료 중/완료) 라벨, 상대+절대시간 병기, 미확인 dot(new/ready),
  로딩 스켈레톤(행 3개), 빈 상태("아직 제출된 문진이 없습니다") 전부 유지.
- 정렬: URGENT 최상단 → 신규 → 최신순. `완료`는 기본 접힘 그룹("오늘 완료 n건").

### 8.4 순서 불변식 검증 방식 교체 (Opus N10)

`DOCTOR_SECTION_ORDER` 배열은 실제 렌더를 구동하지 않는 문서용 상수이며, 2컬럼에서는
DOM 순서 ≠ 시각 순서다. **배열-인덱스 테스트를 폐기하고, 렌더된 HTML의 문자열 인덱스
비교(현행 13a 기법)로 교체한다:**
- 검증 1: URGENT 배너/안전 통합 블록 마크업이 명리·참고 마크업보다 앞선다.
- 검증 2: 헤더 안전 pill 마크업이 문서 최상단 밴드 안에 있다.
- 시각 순서 규칙 명문화: "레일은 우상단이지만, 안전 정보(헤더 pill + 좌측 최상단
  블록)는 항상 레일보다 먼저 스캔되는 위치(상단 밴드 + 좌측 첫 블록)에 있다."

**상태 인코딩 원칙 (Opus P3 반영):** **임상 상태(URGENT/REVIEW/CLEAR/잠금)는
색 + 형태(아이콘 ⚠/⚠/✓/🔒) + 텍스트 라벨의 3중 인코딩이 필수다.** 색-단독 표현 금지

(Opus B2). 확정 값:

| 상태 | 배경 | 좌측 보더 | 아이콘 | 텍스트 |
|---|---|---|---|---|

| CLEAR | `--doctor-mint` | 없음 | ✓ | `--doctor-green` 400 |
| 잠금(locked) | 상태색 유지 | 유지 | 🔒 추가 | 문구 원문 유지 |

## 11. Interaction Specification

### 11.1 안전 상태 단일 출처 — `deriveSafetyOverview(payload)` (Opus B1)

렌더 계층에 selector 함수를 신설한다 (FROZEN 로직 무변경 — 기존 `compute*Flags`
결과의 union만 계산):

```
URGENT  ⟸ flags.requires_staff_check
          || any(module.*_safety_status === 'URGENT_REVIEW')
REVIEW  ⟸ any(module.*_safety_status === 'REVIEW_REQUIRED')
          || any(*Locked === true)
          || flags.response_consistency_review
          || flags.sleep_disorder_priority_review || flags.sleep_disorder_review
CLEAR   ⟸ 그 외 (안전 문진에 실제 응답이 있을 때만 '안전 확인됨' — 미응답이면
          pill 자체를 '안전정보 없음' 중립 표기)
```
- 티어 배치는 **현행 코드의 의미를 그대로 보존**한다 (모듈 URGENT는 StaffCheck
  인터스티셜급이지만 `requires_staff_check`에 이미 불포함인 것을 union으로 복원;
  sleep_disorder_priority는 현행 danger chip에 있으나 배너 제외였으므로 REVIEW 티어 —
  새 임상 threshold 생성 없음).
- **헤더 pill · URGENT 전폭 배너 · 목록 행 배지 · 태블릿 pill 스트립 넷 다 이 selector만
  읽는다.** 다른 계산 경로 금지 (invariant).
- P2 완료 조건: 각 모듈 URGENT fixture → `overview === 'URGENT'` node 테스트.

### 11.2 통합 안전 리스트 행 게이트 (Opus B3)

- 행 생성: **`safety_flags.{lbp,hip,neck,shoulder,knee,elbow,wrist_hand,ankle_foot,tmj}
  !== null`인 모듈 전부.** `primary_module_detail`/`additional_module_detail`은 **정렬
  우선순위에만** 사용, 가시성 게이트 사용 금지 (invariant).
- `showLbpExam`(진찰 소견 radio 노출)도 `safety_flags.lbp !== null`로 변경
  (SHOULDER는 이미 동일 패턴).

### 11.3 통합 안전 리스트 — 접힘·렌더 정책 (Opus B2/M2/M3)

- 한 행 = 한 부위: `아이콘 부위명 [상태] 사유 요약` + 확장 영역.
- **접힘 정책 (상태별 고정):**
  - **URGENT_REVIEW: 항상 확장. 접기 컨트롤 자체를 렌더하지 않는다.**
  - **REVIEW_REQUIRED: 기본 확장** (사유·잠금·권장 검사가 클릭 없이 보인다 — 최빈
    상태에서 클릭 0 유지).
  - CLEAR: 한 줄 접힘 (`✓ 고관절 — 안전`).
- **잠금(fail-closed) 문구는 접힘 여부와 무관하게 행 요약 줄에 항상 노출** (🔒 아이콘
  + 원문).
- **계산 플래그는 `true`인 것만 렌더한다. `false`는 확장 시에도 렌더하지 않는다.**
  단 `안전 확인`/`치료 안전` 상태 자체는 항상 렌더. 확장 영역 하단 상주 문구:
  "위 플래그는 문진 기반 fail-closed 계산 결과이며, 진찰로 확인된 음성 소견이
  아닙니다."
- 부위 행들 아래 "일반 안전정보" 서브 영역: 복용약/병력/임신·수유/알레르기/위험신호
  포인터/수면장애 선별/수술·입원력/추가 전달사항/기타 확인 (현행 safetyGlanceItems
  6종 포함 — Opus N5). 응답 모순은 이 리스트 **최상단 amber 행** + 헤더 배지 이중
  노출 (Opus N4).
- 권장 검사가 없는 모듈(HIP/ANKLE_FOOT/TMJ): 확장 영역에 검사 목록 자체를 미렌더
  (빈 제목 금지 — Opus M4).

### 11.4 오늘 확인 목록 (Opus B4)

- 구성: 권장 검사(suggested*ExamCodes 통합) + 미확인 항목(수술력 종류·추가 전달사항·
  기타 선택) 자동 집계. 권장 검사가 없는 모듈은 해당 항목이 없을 뿐 블록은 미확인
  항목으로 유지; **둘 다 비면 블록·하단 bar 버튼 미렌더.**
- **안전 표시와 완전 분리 (invariant):** 헤더 pill·상태 행·잠금 문구는 오직
  `compute*Flags` 결과로만 결정된다. 체크 상태는 어떤 경우에도 이에 영향을 주지
  않는다.
- 체크박스: **서버 모드에서만, `sessionStorage['doctor_checklist_' + visit_id]`에
  방문 스코프로 지속** (목록↔상세 왕복에도 유지, 브라우저 종료 시 소멸 — 임상 기록
  아님). 카운터는 무채색 회색 `진행 메모 2/4 (비-임상 기록)`. fixtures 모드: 체크박스
  없는 읽기 전용 목록.

### 11.5 EMR 시트 (Opus M5)

- 레일에는 버튼만: `EMR 요약 열기` + 상태 dot(`준비됨`/`녹취 없음`은 버튼 미렌더).
  recorder 결과가 없으면(초진 대부분·fixtures 전부) 버튼 자체가 없다 — 빈 블록 금지.
- 시트(우측 슬라이드 patch, 데스크톱 폭 560px / 태블릿 bottom sheet 60%):
  transcript 펼치기 + EMR textarea + 복사/다시 만들기 — 현행 기능 계약 그대로.
- **자동 덮어쓰기 금지:** 사용자가 textarea를 한 번이라도 편집했으면 새 recording_id
  도착 시 자동 교체하지 않는다. 시트 상단 amber 스트립:
  `새 요약 도착 — [내 편집 유지] [새 요약으로 교체]`. 미편집 상태에서는 현행대로
  자동 seed. (`요약 다시 만들기` = 기존 escape hatch 재사용, 계약 무변경.)

| 상태 | 동작 |
|---|---|

### 11.7 저장 상태 머신 (Opus B5)

```
idle → saving(버튼 비활성+스피너) → saved(서버 200 수신 시각 표시)
                                  → error(사유 + [다시 시도], amber)
```
- **`저장됨`은 서버 200 응답에만 붙는다.** 클라이언트 `recorded_at`(finalizeJudgment의
  시계값)은 "기록 시각"으로 별도 표기하며 저장 보증이 아니다.
- 구현 계약 변경(§14 P3의 명시적 산출물): `JudgmentPanel.onSave: (j) =>
  Promise<ServerResult>`로 변경하고 `handleRecord`가 await + 상태 반영.
  `JudgmentPanel.tsx:273`의 "아직 저장되지 않음" 고정 문구를 상태 머신 표시로 교체
  (P3 완료 조건).
- 단축키: `Ctrl/Cmd+Enter` = 기록은 **판단 폼 내부에 포커스가 있을 때만** 동작
  (전역 바인딩 금지 — Opus P4).

### 11.8 진료 상태 전이 (Opus N2)

- 상단바에 `진료 완료` 버튼 (서버 모드 + 상세 열림 시): `setSubmissionStatus(id,
  'completed')` — 기존 계약 재사용, 신규 계약 없음. 완료 후 목록 복귀, 완료 그룹으로
  이동.
- 열람 시 `viewed` 세팅은 현행 유지. **`in_consultation`을 자동 세팅할지(예: 판단
  저장 시)는 임상 운영 의미가 걸린 결정이므로 Product Owner 승인 항목으로 남긴다**
  (자동 전이 임의 구현 금지).

## 13. 구현 시 반드시 지켜야 할 Invariant

1. FROZEN: `src/spec/*Logic.ts`, `*Adapter.ts` 무변경. **단, `DoctorView.tsx`의 렌더
   게이트는 렌더 계층이다** — 안전 정보 가시성 게이트는 `safety_flags.* !== null`로
   단일화하며, `primary_module_detail`/`additional_module_detail`을 가시성 게이트로
   사용하지 않는다 (v0.1 invariant 1의 "현행 게이트 동결" 문구 폐기 — Opus B3).
2. 안전 정보(헤더 pill·배너·통합 리스트)는 명리·참고보다 항상 먼저 — 검증은 §8.4의
   HTML 문자열 인덱스 방식.
3. 잠금(fail-closed) 문구: 의미 축약 금지 + **접힘 여부와 무관하게 상시 노출**.
4. "안 물어봄 ≠ none/unknown 응답" 유지 + **계산 플래그는 true만 렌더**(§11.3).
5. **안전 pill·상태 행·잠금 표시는 오직 `compute*Flags` 결과로만 결정된다. 로컬 체크
   상태는 어떤 경우에도 이를 변경하지 않는다** (Opus B4).
6. 원장 입력 자동 채움·자동 추천 금지. 체크 상태는 저장 계약 밖(sessionStorage,
   방문 스코프).
7. 진찰 소견 radio는 기존 judgment 저장 경로만 사용. `저장됨` 표시는 서버 200에만.
8. identity: 이름+끝4자리(+성별/나이 파생 태그). **차트번호는 payload 필드 신설 전
   표시 금지. 직전 방문 슬롯은 이력 데이터 모델 도입 전 렌더 금지(플레이스홀더 포함).
   NRS 등 존재하지 않는 척도 표기 금지** (Opus M6).
9. 참고 증상·기타 확인은 urgent보다 강조 금지.
10. 환자 개인정보를 문서·로그·커밋에 실제 값으로 기록 금지.
11. **색 토큰: `.doctor` 스코프 `--doctor-*`만. `:root` 무변경. `html.doctor-mode`
    전역 규칙(styles.css) 무변경. 컬럼별 독립 `overflow` 스크롤 금지**
    (sticky-vs-overflow 이력, Opus P1/M8).
12. 임상 상태는 색+형태+텍스트 3중 인코딩 필수 (색-단독 금지).
